## 1. What Was Implemented

Sprint 3 closes the programmatic access gap: AI agents and service accounts can now authenticate against mcpgate without a browser. Additionally, SAML endpoints are hardened with brute-force detection.

- **Provider-agnostic M2M authentication** via a `jwks_configs` database table. Any OIDC-compatible issuer (Auth0, Okta, Azure AD, Vault PKI) can be registered via the admin API — no code changes, no restart required.
- **JWKS HTTP client** (`internal/auth/jwks/client.go`) — per-issuer RSA public key cache with configurable TTL, double-checked locking, and kid-miss forced refresh.
- **M2M JWT validator** (`internal/auth/jwks/validator.go`) — peeks `iss` claim unverified, looks up issuer in `jwks_configs`, fetches JWKS, verifies RS256 signature + audience + expiry, returns `UserIdentity`.
- **Unified auth middleware** — the existing `Authenticate` middleware now routes tokens to the session JWT path (issuer matches `cfg.JWT.Issuer`) or the M2M JWKS path (any external issuer). The session JWT path is byte-for-byte unchanged — all Sprint 2 tests continue to pass.
- **Brute-force detection** on SAML endpoints — Redis INCR-based counters per IP per endpoint; configurable threshold (default: 10 attempts) and block duration (default: 1h). Reset on successful authentication.
- **Session fixation safety confirmed** — no pre-auth session exists; `uuid.New()` is generated at ACS completion only. A comment was added to make the intent explicit.
- **Admin REST CRUD** for JWKS configs (`/api/v1/admin/jwks/configs`), mirroring the existing IDP config API.
- **Postgres migration** `002_jwks_configs` with a partial index on `issuer WHERE is_enabled = true` optimising the auth hot path.

## 3. Migration (`002_jwks_configs`)

```sql
CREATE TABLE jwks_configs (
    id         UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
    name       TEXT        UNIQUE NOT NULL,
    issuer     TEXT        UNIQUE NOT NULL,
    jwks_url   TEXT        NOT NULL,
    audience   TEXT        NOT NULL DEFAULT '',
    is_enabled BOOLEAN     NOT NULL DEFAULT true,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_jwks_configs_issuer ON jwks_configs (issuer) WHERE is_enabled = true;

CREATE TRIGGER jwks_configs_updated_at
    BEFORE UPDATE ON jwks_configs
    FOR EACH ROW EXECUTE FUNCTION set_updated_at();
```

**Key design choices:**

- Both `name` and `issuer` carry `UNIQUE` constraints — two configs cannot claim the same issuer
- `audience` defaults to `''` (empty string = skip audience check). An empty audience allows providers that do not include an `aud` claim or target multiple audiences with a single config
- The partial index on `issuer WHERE is_enabled = true` means `GetByIssuer` (the auth hot path) uses an index scan over only enabled rows, not a full table scan
- `set_updated_at()` trigger function already exists from migration `001` — no duplicate needed

## 4. Store Layer

### 4.1 `JWKSConfig` Struct and `JWKSConfigStore` Interface (`internal/store/interfaces.go`)

```go
type JWKSConfig struct {
    ID        uuid.UUID
    Name      string
    Issuer    string    // exact match against JWT iss claim
    JWKSURL   string
    Audience  string    // empty string = skip aud check
    IsEnabled bool
    CreatedAt time.Time
    UpdatedAt time.Time
}

type JWKSConfigStore interface {
    Create(ctx context.Context, cfg *JWKSConfig) error
    GetByID(ctx context.Context, id uuid.UUID) (*JWKSConfig, error)
    GetByName(ctx context.Context, name string) (*JWKSConfig, error)
    GetByIssuer(ctx context.Context, issuer string) (*JWKSConfig, error)
    List(ctx context.Context) ([]JWKSConfig, error)
    ListEnabled(ctx context.Context) ([]JWKSConfig, error)
    Update(ctx context.Context, cfg *JWKSConfig) error
    Delete(ctx context.Context, id uuid.UUID) error
}
```

`GetByIssuer` filters to `is_enabled = true`. A disabled config returns `store.ErrNotFound`, causing the middleware to reject the token — same security posture as SAML IdPs.

All columns are scalar (no JSONB) — no marshalling required.

### 4.2 `JWKSConfigStore` Implementation (`internal/store/postgres/jwks.go`)

Mirrors `saml.go` exactly in pattern. Reuses the `isUniqueViolation` helper for both `Create` and `Update`.

| Method | Notes |
|--------|-------|
| `Create` | `RETURNING` all columns; unique violation on `name` or `issuer` → `ErrAlreadyExists` |
| `GetByID` | Single row scan; `ErrNoRows` → `ErrNotFound` |
| `GetByName` | Single row scan |
| `GetByIssuer` | `WHERE issuer = $1 AND is_enabled = true`; `ErrNoRows` → `ErrNotFound` |
| `List` | `ORDER BY name` |
| `ListEnabled` | `WHERE is_enabled = true ORDER BY name` |
| `Update` | Full replace; `RowsAffected() == 0` → `ErrNotFound` |
| `Delete` | `RowsAffected() == 0` → `ErrNotFound` |

## 5. JWKS Client (`internal/auth/jwks/client.go`)

```go
type Client struct {
    url        string
    httpClient *http.Client
    ttl        time.Duration
    mu         sync.RWMutex
    keys       map[string]*rsa.PublicKey // kid → key
    fetchedAt  time.Time
}

func NewClient(url string, ttl time.Duration) *Client
func (c *Client) GetKey(ctx context.Context, kid string) (*rsa.PublicKey, error)
```

**`GetKey` logic — double-checked locking:**

1. `RLock`: cache fresh (`!fetchedAt.IsZero() && time.Since(fetchedAt) < ttl`) and `kid` present → return immediately
2. `RUnlock`, acquire `Lock`
3. Re-check (another goroutine may have fetched while we waited)
4. `fetch(ctx)` — unconditional HTTP GET, replaces key map, updates `fetchedAt`
5. Look up `kid`; `ErrNotFound`-equivalent if absent after fresh fetch

**Kid-miss forced refresh:** if the requested `kid` is absent even after a fresh cache, the slow path is still entered on the next request (because `cacheValid()` is true but kid is missing — the guard `cacheValid() && kid present` fails). This handles rolling key rotation: a new key appears at the JWKS endpoint before the old one expires.

**`fetch` implementation:**
- `http.NewRequestWithContext` to respect ctx cancellation
- `http.StatusOK` check (non-200 → error)
- Decodes `{"keys": [{kty, kid, n, e}]}` — ignores non-RSA keys
- `n` and `e` are base64url-decoded and converted to `*big.Int`; `e` is verified to fit in `int64` before conversion

**`httpClient` timeout:** 30 seconds. Separate from the request context timeout — whichever fires first.

## 6. M2M Validator (`internal/auth/jwks/validator.go`)

```go
type Validator struct {
    store     store.JWKSConfigStore
    clientTTL time.Duration
    logger    *slog.Logger
    mu        sync.RWMutex
    clients   map[string]*Client // issuer → Client
}

func NewValidator(s store.JWKSConfigStore, clientTTL time.Duration, logger *slog.Logger) *Validator
func (v *Validator) ValidateToken(ctx context.Context, tokenStr string) (*auth.UserIdentity, error)
```

**`ValidateToken` steps:**

1. `peekClaim(tokenStr, "iss")` — base64url-decode payload, unmarshal JSON, extract `iss` without signature verification
2. `store.GetByIssuer(ctx, iss)` — disabled or absent issuer → 401 via error propagation
3. `clientFor(cfg.Issuer, cfg.JWKSURL)` — double-checked map lookup (RLock fast path, write lock on first create)
4. `jwt.ParseWithClaims` with `jwt.WithIssuer(cfg.Issuer)` and `jwt.WithExpirationRequired()`, key function that calls `client.GetKey(ctx, kid)`
5. Algorithm guard in key function: `if _, ok := t.Method.(*jwt.SigningMethodRSA); !ok` → reject non-RSA tokens (prevents HS256 confusion attacks)
6. Audience check (if `cfg.Audience != ""`): linear scan of `claims.Audience` for exact match
7. Return `auth.UserIdentity{UserID: uuid.Nil, Email: claims.Subject, Roles: claims.Permissions, SessionID: uuid.Nil}`

**Audience check implementation note:** `jwt/v5` removed `VerifyAudience` from `RegisteredClaims`. Audience verification is done manually with a range loop over `claims.Audience`.

**`Validator.clients` map:** never evicted. Changing `jwks_url` in the database takes effect on the next process restart. This is a known limitation (see §14).

**Custom claims type:**
```go
type m2mClaims struct {
    jwt.RegisteredClaims
    Permissions []string `json:"permissions"` // Auth0 + standard OIDC convention
}
```

`Permissions` → `UserIdentity.Roles`. If nil, normalised to `[]string{}` to avoid nil slice surprises in callers.

**M2M identity semantics:**

| Field | Value | Reason |
|-------|-------|--------|
| `UserID` | `uuid.Nil` | M2M clients are not users table rows |
| `Email` | `claims.Subject` | `sub` is the stable identity string for M2M |
| `Roles` | `claims.Permissions` | From token, not from DB — M2M clients have no `user_roles` rows |
| `SessionID` | `uuid.Nil` | No session record; M2M tokens are stateless |

## 8. Middleware Changes (`internal/auth/middleware.go`)

### 8.1 `M2MValidator` Interface

```go
// M2MValidator validates externally-issued JWTs from configured JWKS providers.
// Nil disables M2M authentication. *jwks.Validator satisfies it.
type M2MValidator interface {
    ValidateToken(ctx context.Context, tokenString string) (*UserIdentity, error)
}
```

Defined in `middleware.go` alongside `TokenValidator` to keep the `jwks` package free of HTTP concerns. `*jwks.Validator` satisfies it without an explicit `interface{}` assertion anywhere.

### 8.2 `peekIssuer` Helper

```go
func peekIssuer(tokenString string) string
```

Decodes the JWT payload (second segment) from base64url without verifying the signature. Returns `""` on any parse failure. Used **only for routing** — the chosen validator performs full signature verification. Returns a plain `string` (no error) since all failure cases are equivalent to "unknown issuer" for routing purposes.

### 8.3 Updated `Authenticate` Signature

```go
func Authenticate(
    validator    TokenValidator,  // mcpgate session JWTs
    m2mValidator M2MValidator,    // nil disables M2M
    sessionCache store.SessionCache,
    cfg          config.AuthConfig,
    logger       *slog.Logger,
) func(http.Handler) http.Handler
```

### 8.4 Routing Logic

```go
iss := peekIssuer(tokenStr)

switch {
case iss == cfg.JWT.Issuer || iss == "":
    // Session JWT path — byte-for-byte unchanged from Sprint 2
    claims, err := validator.Validate(tokenStr)
    ...
    sessionData, err := sessionCache.Get(ctx, sessionID)
    ...
    identity = UserIdentity{from sessionData}

case m2mValidator != nil:
    // M2M path — external issuer resolved via JWKS
    id, err := m2mValidator.ValidateToken(ctx, tokenStr)
    ...
    identity = *id

default:
    writeAuthError(w, "invalid token")
    return
}
```

The switch form (replacing if-else chain) satisfies the `gocritic ifElseChain` lint rule.

An empty `iss` (unparseable payload, or iss field absent) falls into the session JWT path. If that path then fails validation, the session JWT validator returns a meaningful error. This is the correct fallback: tokens without an `iss` claim are almost certainly mcpgate-issued session tokens (the `jwtpkg.Manager` sets `iss = cfg.Issuer` on every issued token).

## 9. Brute-Force Detection (`internal/auth/saml/brute_force.go`)

### 9.1 Interface and Adapter

```go
// redisCounter abstracts the three Redis operations BruteForceGuard needs.
// This narrow interface makes the guard unit-testable without a real Redis.
type redisCounter interface {
    Incr(ctx context.Context, key string) (int64, error)
    Expire(ctx context.Context, key string, d time.Duration) (bool, error)
    Del(ctx context.Context, keys ...string) (int64, error)
}
```

`*redis.Client` does not directly satisfy `redisCounter` (its methods return `*redis.IntCmd`, not `(int64, error)`). A private `redisAdapter` struct wraps `*redis.Client` and calls `.Result()` on each command. This adapter is created inside `NewBruteForceGuard` — callers pass a plain `*redis.Client`.

### 9.2 `BruteForceGuard` Struct

```go
type BruteForceGuard struct {
    redis       redisCounter
    maxAttempts int64
    window      time.Duration
    blockFor    time.Duration
    enabled     bool
}
```

### 9.3 `Check` Logic

```go
func (g *BruteForceGuard) Check(ctx context.Context, key string) bool
```

1. `enabled == false` → return `false` immediately
2. `INCR key` → on Redis error, return `false` (availability over enforcement)
3. `count == 1` → set TTL to `window` (first request in window starts the expiry clock)
4. `count > maxAttempts` → extend TTL to `blockFor` (repeat offenders stay blocked after their first block expires), return `true`
5. return `false`

**Key scheme:** `brute:<endpoint>:<ip>` — e.g., `brute:saml_login:192.0.2.1`.

**Reset:** `Del(ctx, key)` — called on successful SAML authentication. Both `brute:saml_login:<ip>` and `brute:saml_acs:<ip>` are reset.

### 9.4 Integration with `Handlers`

`guard *BruteForceGuard` added to `Handlers` struct. Initialised inside `NewHandlers` from the existing `redisClient *redis.Client` and `authCfg.BruteForce` parameters — no signature change.

**Login handler:** guard check runs after the `sp.Configured()` gate, before IdP lookup. IP is extracted from `r.RemoteAddr` using `net.SplitHostPort` (port stripped for INET compatibility).

**ACS handler:** guard check runs after `sp.Configured()` gate, before form parsing. Same IP extraction (the `clientIP` variable declared here is reused for the Reset calls later — removed the duplicate declaration that previously existed at the session creation point).

**Reset on success:** called before JWT issuance:
```go
h.guard.Reset(r.Context(), "brute:saml_login:"+clientIP)
h.guard.Reset(r.Context(), "brute:saml_acs:"+clientIP)
```

## 10. Session Fixation (`internal/auth/saml/handlers.go`)

**Finding:** No code change required.

The ACS handler always generates a fresh session ID at completion:
```go
// sessionID is always newly generated here — no pre-auth session exists to fix.
// Create durable session.
sessionID := uuid.New()
```

No session record or cookie exists before this line. The SAML `AuthnRequest.ID` embedded in `RelayState` is the CSRF protection mechanism — it is bound to the user's browser tab, not to any server-side session. Session fixation is structurally impossible.

A comment was added to make this invariant explicit for future readers.


| # | Decision | Rationale |
|---|----------|-----------|
| D1 | `jwks_configs` table mirrors `saml_idp_configs` pattern | Consistent admin API surface; adding a provider is a data operation, not a code deploy or restart |
| D2 | `peekIssuer` reads iss without signature verification | Safe — only used for routing to the correct validator; the validator verifies the signature |
| D3 | `M2MValidator` is a separate interface from `TokenValidator` | `TokenValidator` returns `*jwtpkg.Claims` (mcpgate-specific struct). M2M returns `*UserIdentity`. Keeping them separate avoids forcing a refactor of the session JWT path and its tests |
| D4 | `UserID: uuid.Nil` for M2M identities | M2M clients are not users table rows; roles come from the `permissions` JWT claim, not from `user_roles` |
| D5 | `Validator.clients` map never evicted | JWKS configs change rarely; acceptable for Sprint 3. Changing `jwks_url` takes effect on restart. Documented as known gap |
| D6 | `BruteForceGuard` takes a `redisCounter` interface | Keeps guard unit-testable without a real Redis instance; `*redis.Client` is adapted internally |
| D7 | `redisAdapter` wraps `*redis.Client` rather than changing `NewBruteForceGuard` to take an interface | Callers (server.go, NewHandlers) hold a `*redis.Client` — they should not care about the interface. Adapter is a private implementation detail |
| D8 | `audience == ""` skips aud check | Some JWKS providers do not include `aud` claims; making it optional avoids breaking those configs while still enforcing audience for providers that use it |
| D9 | `peekIssuer` returns `""` on parse failure (not an error) | Every failure case is equivalent to "treat as session JWT" for routing. Propagating the error would require the middleware to handle it, adding complexity for no benefit |
| D10 | Brute-force counters reset on ACS success, not on Login success | Login success only means the redirect was built; authentication is completed at ACS. Resetting at Login would allow an attacker to bypass limits by alternating between login initiations and failed ACS attempts |

## 15. Modifications to Original Sprint 3 Plan

### 15.1 `VerifyAudience` removed in jwt/v5

The plan specified:
```go
if !claims.VerifyAudience(cfg.Audience, true) { ... }
```

`VerifyAudience` was removed from `jwt.RegisteredClaims` in golang-jwt/jwt v5. The implementation uses a manual range loop over `claims.Audience []string` instead.

### 15.2 `peekIssuer` signature simplified

The plan specified `func peekIssuer(...) (string, error)`. After implementation the error return was always `nil` (parse failures result in an empty string, which routes to the session JWT path). The unparam linter flagged this; the signature was simplified to return `string` only.

### 15.3 `redisCounter` interface uses plain values, not redis.Cmd types

The plan's interface sketch used `*redis.IntCmd` and `*redis.BoolCmd` return types (matching `*redis.Client` directly). The implementation uses `(int64, error)` and `(bool, error)` with a private `redisAdapter` wrapper. This makes the interface mockable in unit tests without constructing `*redis.IntCmd` objects (which have no documented stable constructor in go-redis v9's public API).

### 15.4 Duplicate `clientIP` declaration removed from ACS

The original ACS handler already declared `clientIP` near the session creation block. When the brute-force guard check was added at the top of ACS (which also needs the client IP), the duplicate declaration caused a compile error. The second declaration was removed; the variable declared for the guard check is reused throughout the function.
