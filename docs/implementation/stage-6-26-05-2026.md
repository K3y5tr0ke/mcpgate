## 1. What Was Implemented

Sprint 6 adds runtime observability and resilience to the operational layer of mcpgate. Every proxied request is now measured (Prometheus counter + histogram), traced (OpenTelemetry span), and subject to a per-user sliding-window rate limit. Each upstream MCP server is individually protected by a lock-free circuit breaker that trips after a configurable failure threshold and probes recovery automatically.

Six carry-forward items from Sprint 5 were also resolved in this sprint, completing the audit log pipeline and hardening the proxy transport layer.

### Core deliverables

- **Prometheus metrics collector** (`internal/metrics/collector.go`) — dedicated `prometheus.Registry`, 7 metric families, HTTP handler exposed on a separate port, chi middleware for per-request counters and latency histograms.
- **OpenTelemetry tracing provider** (`internal/tracing/provider.go`) — wraps `sdktrace.TracerProvider`; returns a no-op provider when OTLP is disabled so downstream code never needs nil-guards on spans.
- **Redis sliding-window rate limiter** (`internal/store/redis/rate_limiter.go`) — Lua script (ZREMRANGEBYSCORE + ZCARD + ZADD + PEXPIRE) loaded once at construction; atomically checks RPM then RPD; fails open on Redis error.
- **Rate limit middleware** (`internal/ratelimit/middleware.go`) — per-user 429 with `Retry-After` header and a valid JSON-RPC `-32000` error body; wired after auth and before RBAC.
- **Per-server circuit breaker** (`internal/proxy/circuitbreaker/breaker.go`) — lock-free state machine (Closed → Open → HalfOpen → Closed) using `atomic.Int32` CAS; integrated into `proxy.Handler` via a `sync.Map` keyed by server name.
- **Dedicated metrics HTTP server** — bound to `cfg.Server.MetricsPort` (default 9090) on a separate listener created synchronously in `New()`.
- **Enhanced `/ready` health check** — returns component-level JSON for database, Redis, and pipeline; HTTP 503 when any critical component is down.
- **`/healthz` / `/readyz` aliases** — Kubernetes-compatible liveness/readiness endpoints.
- **Migration 004** — composite index on `(timestamp ASC, id ASC)` and unique index on `hash_chain` for retention query efficiency and future WAL replay idempotency.

## 4. Metrics (`internal/metrics/collector.go`)

### Registered metrics

| Metric | Type | Labels | Description |
|--------|------|--------|-------------|
| `mcpgate_requests_total` | Counter | `server`, `method`, `status`, `auth_type` | Total proxied MCP requests |
| `mcpgate_request_duration_seconds` | Histogram | `server`, `method`, `status` | End-to-end latency from middleware entry to response |
| `mcpgate_active_requests` | Gauge | `server` | In-flight requests (Inc on enter, Dec via defer) |
| `mcpgate_rate_limit_hits_total` | Counter | `window` | Requests rejected by rate limiter (`rpm` or `rpd`) |
| `mcpgate_circuit_breaker_state` | Gauge | `server` | `0`=closed, `1`=open, `2`=half-open |
| `mcpgate_upstream_errors_total` | Counter | `server`, `error_type` | Transport errors classified as `timeout`, `connection_refused`, `dns_error`, `upstream_error` |
| `mcpgate_auth_failures_total` | Counter | `reason` | Auth rejections by reason (available for auth middleware to populate) |
| `mcpgate_audit_pipeline_dropped_total` | GaugeFunc | — | `pipeline.DroppedCount()` sampled at scrape time via `prometheus.NewGaugeFunc` |

All metrics use a **dedicated `prometheus.Registry`** (not the default global). This is critical for test isolation: multiple test instances each create a `Collector`, and their counters never interfere.

### Import cycle resolution

`metrics` imports `proxy` (for `proxy.MessageFromContext` and `proxy.MessageFromContext` in the middleware). `proxy` cannot import `metrics` without a cycle. The solution: define a `ProxyMetrics` interface in `internal/proxy/handler.go` that `metrics.Collector` satisfies:

```go
// In internal/proxy/handler.go — consumed here, implemented in metrics.
type ProxyMetrics interface {
    RecordCircuitState(server string, state float64)
    RecordUpstreamError(server, errorType string)
}
```

`Handler` holds a `pm ProxyMetrics` field (nil when metrics are disabled). `Handler.WithMetrics(pm ProxyMetrics)` sets it after construction. `metrics.Collector` implements the interface through `RecordCircuitState` and `RecordUpstreamError` methods. No import of the `metrics` package is needed in `proxy`.

### Metrics middleware

```go
func (c *Collector) Middleware() func(http.Handler) http.Handler {
    return func(next http.Handler) http.Handler {
        return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
            server := chi.URLParam(r, "serverName")
            c.ActiveRequests.WithLabelValues(server).Inc()
            defer c.ActiveRequests.WithLabelValues(server).Dec()

            ww := chimw.NewWrapResponseWriter(w, r.ProtoMajor)
            start := time.Now()
            next.ServeHTTP(ww, r)
            elapsed := time.Since(start).Seconds()

            method := ""
            if msg := proxy.MessageFromContext(r.Context()); msg != nil {
                method = msg.Method
            }
            authType := "session"
            if identity := auth.IdentityFromContextOrZero(r.Context()); identity.SessionID == uuid.Nil {
                authType = "m2m"
            }
            status := statusLabel(ww.Status())
            c.RequestsTotal.WithLabelValues(server, method, status, authType).Inc()
            c.RequestDuration.WithLabelValues(server, method, status).Observe(elapsed)
        })
    }
}
```

`statusLabel` maps HTTP status codes to coarse strings (`"2xx"`, `"3xx"`, `"4xx"`, `"5xx"`) to prevent high label cardinality.

### Metrics HTTP server

The Prometheus endpoint runs on a dedicated `net.Listener` on `cfg.Server.MetricsPort`. The listener is created **synchronously** inside `server.New()` (see §10 — deviation from plan) so that `MetricsAddr()` is available before `New()` returns:

```go
metricsLn, err := net.Listen("tcp", fmt.Sprintf(":%d", cfg.Server.MetricsPort))
if err != nil {

}
```

`metricsLn.Addr().String()` is stored in `Server.metricsAddr` (e.g. `"127.0.0.1:9090"`) and exposed via `MetricsAddr() string` for E2E tests that need to scrape the metrics endpoint. The metrics server also serves `/healthz` as a simple liveness endpoint on the same port.

## 5. Tracing (`internal/tracing/provider.go`)

### Design

The `Provider` wraps an `*sdktrace.TracerProvider`. When `cfg.OTLP.Enabled == false`, a no-op provider from the `go.opentelemetry.io/otel/trace/noop` package is used. The global `otel.SetTracerProvider` and `otel.SetTextMapPropagator` are set regardless, so calls to `trace.SpanFromContext(ctx)` in any downstream code are always safe without nil-guards.

```go
type Provider struct {
    tp     *sdktrace.TracerProvider // nil when no-op
    tracer trace.Tracer
}
```

### No-op path

```go
if !cfg.Enabled {
    noop := tracenoop.NewTracerProvider()
    otel.SetTracerProvider(noop)
    otel.SetTextMapPropagator(propagation.NewCompositeTextMapPropagator(
        propagation.TraceContext{},
        propagation.Baggage{},
    ))
    return &Provider{tracer: noop.Tracer(serviceName)}, nil
}
```

Note: `trace.NewNoopTracerProvider()` (the original plan) is deprecated as of OTel v1.20. The implementation uses the replacement `tracenoop.NewTracerProvider()` from `go.opentelemetry.io/otel/trace/noop`.

### OTLP path

```go
conn, err := grpc.NewClient(cfg.Endpoint, opts...)
exporter, err := otlptracegrpc.New(ctx, otlptracegrpc.WithGRPCConn(conn))
tp := sdktrace.NewTracerProvider(
    sdktrace.WithBatcher(exporter),
    sdktrace.WithResource(res),
    sdktrace.WithSampler(sdktrace.AlwaysSample()),
)
```

`grpc.NewClient` (not the deprecated `grpc.Dial`) is used. When `cfg.Insecure` is true, `grpc.WithTransportCredentials(insecure.NewCredentials())` is added — appropriate for local Jaeger/Tempo collectors in development.

### Middleware

```go
func (p *Provider) Middleware() func(http.Handler) http.Handler {
    return otelhttp.NewMiddleware("mcpgate",
        otelhttp.WithTracerProvider(otel.GetTracerProvider()),
        otelhttp.WithPropagators(otel.GetTextMapPropagator()),
        otelhttp.WithSpanNameFormatter(func(_ string, r *http.Request) string {
            if rctx := chi.RouteContext(r.Context()); rctx != nil && rctx.RoutePattern() != "" {
                return r.Method + " " + rctx.RoutePattern()
            }
            return r.Method + " " + r.URL.Path
        }),
    )
}
```

The span name formatter uses the **chi route pattern** (e.g. `POST /mcp/{serverName}/message`) rather than the actual URL path (e.g. `POST /mcp/my-server/message`). Without this, each unique server name would create a separate span name, producing unbounded cardinality in trace storage.

The tracing middleware is registered **globally** in `buildRouter()` (after `chimw.RequestID` and `chimw.Recoverer`), before any route groups. Every request — including health checks, SAML routes, and auth failures — receives a span.

### `Shutdown`

```go
func (p *Provider) Shutdown(ctx context.Context) error {
    if p.tp == nil { return nil } // no-op provider
    return p.tp.Shutdown(ctx)
}
```

Called from `server.Shutdown()` with a 5-second context to flush the OTLP batch exporter before process exit. Safe to call on a no-op provider.

## 6. Rate Limiting

### Redis implementation (`internal/store/redis/rate_limiter.go`)

#### Sliding window Lua script

```lua
local key    = KEYS[1]
local now    = tonumber(ARGV[1])
local window = tonumber(ARGV[2])
local limit  = tonumber(ARGV[3])
local member = ARGV[4]

redis.call('ZREMRANGEBYSCORE', key, '-inf', now - window)
local count = tonumber(redis.call('ZCARD', key))

if count < limit then
    redis.call('ZADD', key, now, member)
    redis.call('PEXPIRE', key, window)
    return {1, limit - count - 1, 0}
else
    local oldest = redis.call('ZRANGE', key, 0, 0, 'WITHSCORES')
    local retry_ms = 0
    if #oldest >= 2 then
        retry_ms = math.max(0, tonumber(oldest[2]) + window - now)
    end
    return {0, 0, retry_ms}
end
```

The script is **loaded once** via `ScriptLoad` at construction time. Subsequent calls use `EvalSha` (the script's SHA1 digest) which avoids resending the script body on every request. If Redis is restarted (NOSCRIPT error), the script is automatically reloaded and the call retried once.

**Key scheme:**
- Per-user RPM window: `ratelimit:rpm:<userID>` (window = 60,000ms)
- Per-user RPD window: `ratelimit:rpd:<userID>` (window = 86,400,000ms)

**Member uniqueness:** Uses `fmt.Sprintf("%d-%p", nowMS, &nowMS)` — cheap and sufficiently unique within a single process. A UUID would be more robust under multi-process scenarios but adds allocation overhead for every request.

**Fail-open:** Any Redis error (network partition, timeout) returns `(RateLimitResult{Allowed: true}, err)`. Rate limiting is a capacity protection mechanism, not a security control — a brief outage should not deny all requests.

#### Middleware (`internal/ratelimit/middleware.go`)

```go
func Middleware(
    limiter store.RateLimiter,
    cfg config.RateLimitingConfig,
    col *metrics.Collector,
    logger *slog.Logger,
) func(http.Handler) http.Handler
```

Logic:
1. If `!cfg.Enabled || limiter == nil` → pass through immediately.
2. `auth.MustIdentity(ctx)` → rate limit is always per authenticated user (identity guaranteed by `authMiddleware` which runs before this).
3. Single `limiter.Allow(ctx, userKey, limit)` call — the implementation internally checks RPM first, then RPD.
4. If denied: increment `mcpgate_rate_limit_hits_total{window="rpm"}` (or `"rpd"`), write HTTP 429.
5. On limiter error: log warning, fail open, call `next`.

The 429 response body is a valid JSON-RPC 2.0 error so MCP clients receive a parseable response:

```json
{
  "jsonrpc": "2.0",
  "id": <from context if available, else null>,
  "error": {
    "code": -32000,
    "message": "rate limit exceeded",
    "data": {"retry_after_seconds": 42}
  }
}
```

The request ID is read from `proxy.MessageFromContext(r.Context())` — populated by the logging middleware which runs upstream. The `Retry-After` HTTP header is also set for HTTP-layer clients.

**Wiring position:** After `authMiddleware` (identity required), after `logging.Middleware` (message in context), after `metricsCollector.Middleware()` (so rate-limited requests are counted in the histogram), before `rbac.Authorize`.

## 7. Circuit Breaker (`internal/proxy/circuitbreaker/breaker.go`)

### State machine

```
            failures >= threshold
  Closed  ───────────────────────► Open
    ▲                                │
    │  HalfOpenMaxRequests succeed   │ RecoveryTimeout elapsed
    │                                ▼
    └────────────────────────── HalfOpen ──► Open (any failure)
```

States are stored in `atomic.Int32`. All transitions use `CompareAndSwap` so the machine is safe for concurrent goroutines without any mutex.

### `Allow() bool`

```
StateClosed  → true (always)
StateOpen    → if time.Since(openedAt) >= RecoveryTimeout:
                   CAS Open→HalfOpen (only first goroutine wins)
                   return true  (let this request probe)
               else:
                   return false  (fast-fail)
StateHalfOpen → halfOpenCount.Load() < HalfOpenMaxRequests
```

The Open→HalfOpen CAS uses `atomic.Int32.CompareAndSwap`. The goroutine that loses the race (another goroutine already transitioned) still returns `true` as an optimistic probe — the intent is to let some requests through, not exactly one.

### `RecordFailure()`

```
StateHalfOpen → CAS HalfOpen→Open, record openedAt
StateClosed   → failures.Add(1); if failures >= FailureThreshold: CAS Closed→Open, record openedAt
StateOpen     → failures.Add(1) (counter advances, openedAt not reset — window does not extend)
```

**Exhaustive switch**: lint tool `exhaustive` flags any `switch` on a typed const that lacks a `default` or doesn't cover all values. `RecordSuccess` and `RecordFailure` use explicit `case StateClosed, StateOpen:` branches rather than `default:` to document intent and satisfy the linter.

### Integration in `proxy.Handler`

`Handler` gains:
- `pm ProxyMetrics` — nil when metrics are disabled; set via `WithMetrics(pm)`
- `breakers sync.Map` — keyed by server name, value `*circuitbreaker.CircuitBreaker`; lazily populated via `LoadOrStore`

```go
func (h *Handler) callWithCircuitBreaker(serverName string, fn func() ([]byte, error)) ([]byte, error) {
    cb := h.circuitBreakerFor(serverName)

    if !cb.Allow() {
        if h.pm != nil {
            h.pm.RecordCircuitState(serverName, float64(circuitbreaker.StateOpen))
        }
        return nil, fmt.Errorf("circuit open for server %q", serverName)
    }

    resp, err := fn()
    if err != nil {
        cb.RecordFailure()
        if h.pm != nil {
            h.pm.RecordUpstreamError(serverName, classifyError(err))
        }
    } else {
        cb.RecordSuccess()
    }
    if h.pm != nil {
        h.pm.RecordCircuitState(serverName, float64(cb.State()))
    }
    return resp, err
}
```

Note: `ctx context.Context` was removed from `callWithCircuitBreaker`'s signature. The original plan included it, but `unparam` lint flagged it as always unused — transport context is passed directly through `fn()`.

When the circuit is open, `HandleStreamableHTTP` returns **HTTP 200** (consistent with all JSON-RPC error handling in the proxy) with a JSON-RPC internal error body and a `Retry-After` header:

```go
if strings.Contains(err.Error(), "circuit open") {
    cb := h.circuitBreakerFor(serverName)
    w.Header().Set("Retry-After", fmt.Sprintf("%.0f", cb.RecoveryRemaining().Seconds()))
    h.writeError(w, msg.ID, CodeInternalError, fmt.Sprintf("server %q circuit open", serverName))
}
```

The plan described HTTP 502 for circuit-open responses. The implementation uses HTTP 200 to remain consistent with the `writeError` helper (JSON-RPC mandates 200 for application-level errors). The `Retry-After` header provides equivalent signalling for HTTP-aware clients.

## 8. Carry-Forward Items

### CF1 — WAL Replay Atomicity (`internal/logging/sinks/wal.go`)

**Problem:** Sprint 5's `Replay` read entries → called `primary.Write` → truncated the file. A crash between Write and Truncate would replay entries again on restart, producing duplicates.

**Fix:** Atomic rename pattern:

1. `os.Rename(path, path+".replaying")` — atomic on POSIX. If it succeeds, the original file is gone; new writes go to a fresh file.
2. `os.Open(path+".replaying")` — scan all entries.
3. `primary.Write(ctx, entries)` — write to Postgres.
4. **Success:** `os.Remove(path+".replaying")` — only after confirmed write.
5. **Failure:** `os.Rename(path+".replaying", path)` — restore for next attempt.

On startup (`server.New()`), if a `.replaying` file exists (left by a previous crash), it is renamed back to the original path so the background replay goroutine picks it up conservatively:

```go
if _, err := os.Stat(replayingPath); err == nil {
    _ = os.Rename(replayingPath, cfg.Logging.Pipeline.WALPath)
    logger.Warn("wal: .replaying file found on startup; crash recovery rename done")
}
```

This reduces (but does not eliminate) the duplicate-insert window. True idempotency requires `INSERT ... ON CONFLICT (hash_chain) DO NOTHING` — deferred until migration 004's unique index is deployed in all environments.

### CF2 — ClientIP INET Suffix (`internal/store/postgres/audit_logs.go`)

**Problem:** `client_ip::text` in PostgreSQL returns `127.0.0.1/32`; the Sprint 5 workaround stripped the `/32` suffix in `scanAuditEntry` with `strings.SplitN`.

**Fix:** Replace every `client_ip::text` occurrence in `Query`, `Export`, and `VerifyHashChain` SQL with `host(client_ip)`. The PostgreSQL `host()` function returns the bare IP address without the prefix length. The `strings.SplitN` strip in `scanAuditEntry` is removed.

No migration needed — only the SQL cast function changes; the column type remains `INET`.

### CF3 — Hash Chain Tamper-Detection API (`internal/admin/api/logs.go`)

New handler added to `logHandler`:

```go
func (h *logHandler) verify(w http.ResponseWriter, r *http.Request) {
    q := r.URL.Query()
    from, err := time.Parse(time.RFC3339, q.Get("from"))
    // ... to, genesis parsed similarly ...
    ok, err := h.store.VerifyHashChain(r.Context(), from, to, genesis)
    writeJSON(w, http.StatusOK, map[string]any{"ok": ok, "from": from, "to": to})
}
```

Route: `r.Get("/logs/verify", lh.verify)` under the admin + `RequireRole("admin")` group.

The `genesis` parameter is caller-supplied. An incorrect genesis returns `ok: false` — there is no security bypass because the verification logic either matches the stored hashes or it does not.

### CF4 — Log Retention Enforcement

**`AuditLogStore.DeleteExpired`** (added to `store.AuditLogStore` interface and `pgstore.AuditLogStore` implementation):

```go
func (s *AuditLogStore) DeleteExpired(ctx context.Context, hotDays int) (int64, error) {
    tag, err := s.db.Exec(ctx,
        `DELETE FROM audit_logs WHERE timestamp < now() - ($1 || ' days')::interval`,
        hotDays,
    )
    return tag.RowsAffected(), err
}
```

The interval cast `($1 || ' days')::interval` avoids type ambiguity with bare `INTERVAL` literals when using positional parameters.

**Background goroutine** in `server.New()` (only when `HotDays > 0`):
```go
go func() {
    ticker := time.NewTicker(24 * time.Hour)
    defer ticker.Stop()
    for {
        select {
        case <-ticker.C:
            n, err := auditStore.DeleteExpired(bgCtx, cfg.Logging.Retention.HotDays)
            // log result
        case <-bgCtx.Done():
            return
        }
    }
}()
```

The first tick fires after 24 hours — there is no immediate deletion at startup, which is appropriate for a data-retention operation.

### CF5 — WS Stream Authentication

**Verification:** chi evaluates all `r.Use(...)` middleware before the route handler. `RequireRole("admin")` is registered on the admin route group, so it runs before `stream` is called and before `wsUpgrader.Upgrade`. If the role check fails, the middleware writes a 403 and returns — the WebSocket upgrade never happens.

**Browser WS clients:** Browsers cannot set `Authorization` headers on WebSocket upgrade requests. The auth middleware already falls back to the `mcpgate_session` cookie (set by the SAML ACS handler), so SAML-authenticated browser clients work transparently.

**`?token=` explicitly rejected:** A comment in the `stream` handler documents this:
> URL parameters appear in server access logs, proxy logs, and browser history. Adding `?token=` would leak bearer tokens. The cookie path is the correct alternative for browser WebSocket clients.

```go
    endpoint, _ := srv.Config["endpoint"].(string)
    if endpoint == "" {
        endpoint, _ = srv.Config["url"].(string) // common alias in API payloads
    }
```

Accepts `"http"` as an alias for `"streamable_http"` (the formal transport name) and `"url"` as an alias for `"endpoint"` in the config map. This makes the admin API more tolerant of common naming variants and eliminates the E2E test friction that revealed the gap.

## 9. Migration 004

**`internal/store/postgres/migrations/004_audit_log_indexes.up.sql`:**

```sql
CREATE INDEX CONCURRENTLY IF NOT EXISTS idx_audit_logs_timestamp_id
    ON audit_logs (timestamp ASC, id ASC);

CREATE UNIQUE INDEX CONCURRENTLY IF NOT EXISTS idx_audit_logs_hash_chain
    ON audit_logs (hash_chain);
```

**Purpose:**
- `idx_audit_logs_timestamp_id` — supports the range scan in `DeleteExpired` (`WHERE timestamp < now() - interval`) without a full table scan. The `id` secondary column gives a deterministic tiebreaker for `VerifyHashChain`'s `ORDER BY timestamp ASC, id ASC`.
- `idx_audit_logs_hash_chain` (UNIQUE) — enables a future `INSERT ... ON CONFLICT (hash_chain) DO NOTHING` in `BatchInsert`, which would make WAL replay truly idempotent. The index is created now so it is present before that code change is deployed.

`CONCURRENTLY` avoids a table lock on the (potentially large) `audit_logs` table during migration. Both are `IF NOT EXISTS` / `IF EXISTS` for idempotency.

**`004_audit_log_indexes.down.sql`:**

```sql
DROP INDEX CONCURRENTLY IF EXISTS idx_audit_logs_timestamp_id;
DROP INDEX CONCURRENTLY IF EXISTS idx_audit_logs_hash_chain;
```

### `handleReady` — enhanced readiness check

Returns component-level JSON with per-component `status`, optional `latency_ms`, and a `detail` string:

```json
{
  "status": "ok",
  "components": {
    "database": {"status": "ok", "latency_ms": 2},
    "redis":    {"status": "ok", "latency_ms": 1},
    "pipeline": {"status": "ok", "detail": "dropped_total=0"}
  }
}
```

Database and Redis are **critical** — a failure sets overall `"status": "error"` and HTTP 503. Pipeline is **non-critical** — dropped entries set overall `"status": "degraded"` but HTTP 200 so readiness probes do not unnecessarily evict the pod.

The plan's design included upstream circuit-breaker states in the `components` map. The final implementation omits this — the circuit breaker map is internal to `proxy.Handler` and not exposed via an accessor. Upstream state is visible via the `mcpgate_circuit_breaker_state` Prometheus gauge instead.

### `Shutdown()` — updated sequence

```go
func (s *Server) Shutdown() {
    ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
    defer cancel()

    _ = s.metricsServer.Shutdown(ctx)   // stop accepting scrape requests
    _ = s.tracingProvider.Shutdown(ctx) // flush OTLP batch exporter
    s.bgCancel()                         // stop JWKS, session cleanup, WAL replay, retention goroutines
    s.pipeline.Drain()                   // flush remaining audit log entries (last — handlers may still be active)
}
```

## 11. Bugs Discovered During Implementation

### Bug 1 — Import cycle (metrics ↔ proxy)

**Symptom:** Adding `"github.com/K3y5tr0ke/mcpgate/internal/metrics"` to `proxy/handler.go` imports triggered a compile error: `import cycle not allowed` (metrics → proxy → metrics).

**Root cause:** `metrics.Collector.Middleware()` imports `proxy.MessageFromContext` to label metrics with the MCP method. If `proxy/handler.go` also imported `metrics`, the cycle would be: `proxy` → `metrics` → `proxy`.

**Fix:** Define a `ProxyMetrics` interface in `internal/proxy/handler.go` (where it is consumed). `metrics.Collector` implements the interface by satisfying the two methods. `proxy` holds a `pm ProxyMetrics` field and never imports the `metrics` package. This is the standard Go pattern for breaking cycles via interface inversion.

---

### Bug 2 — `callWithCircuitBreaker` unused `ctx` parameter

**Symptom:** `golangci-lint` (`unparam`) reported `ctx context.Context — always receives context.Context from callers, parameter can be removed`.

**Root cause:** The parameter was planned to allow injecting a context-with-timeout into circuit breaker calls. In the implementation, the transport call uses `r.Context()` captured in the closure (`fn`), not the `ctx` parameter.

**Fix:** Removed `ctx context.Context` from the `callWithCircuitBreaker` signature. Both call sites in `HandleStreamableHTTP` and `HandleSSEMessage` updated accordingly. Used `replace_all` to remove `r.Context(), ` from both call sites simultaneously.

---

### Bug 3 — `trace.NewNoopTracerProvider()` deprecated

**Symptom:** `staticcheck SA1019` — `trace.NewNoopTracerProvider is deprecated: use go.opentelemetry.io/otel/trace/noop.NewTracerProvider instead`.

**Fix:** Import `tracenoop "go.opentelemetry.io/otel/trace/noop"` and use `tracenoop.NewTracerProvider()` instead of the deprecated function in `internal/tracing/provider.go`.

---

### Bug 4 — `enabledCfg` second parameter always 0

**Symptom:** `golangci-lint` (`unparam`) on `internal/ratelimit/middleware_test.go` — `rpd int — always receives 0`.

**Root cause:** The test helper `enabledCfg(rpm, rpd int)` was defined with an RPD parameter but all five call sites passed `0`.

**Fix:** Changed the signature to `enabledCfg(rpm int)` and removed `, 0` from all five call sites using `replace_all` on `, 0)` → `)`.

---

### Bug 5 — Metrics server `Retry-After` header (G112 Slowloris)

**Symptom:** `gosec G112` — `net/http: potential Slowloris attack because ReadHeaderTimeout is not configured`.

**Fix:** Added `ReadHeaderTimeout: 10 * time.Second` to the `&http.Server{}` literal for the metrics server.

---

### Bug 6 — `os.Open(replayingPath)` flagged as G304

**Symptom:** `gosec G304` — `Potential file inclusion via variable`.

**Root cause:** `replayingPath` is constructed from the configured `WALPath`, not user input, but `gosec` cannot infer this.

**Fix:** Added `//nolint:gosec // replayingPath is derived from the configured WALPath, not user input` annotation on the `os.Open` call.

---

### Bug 7 — Missing `go.sum` entries for Prometheus transitive dependencies

**Symptom:** `go build ./...` failed with `missing go.sum entry for module providing package github.com/prometheus/...`.

**Fix:** `go get github.com/prometheus/client_golang/prometheus@v1.22.0 && go mod tidy` resolved all missing checksums by pulling transitive dependencies into `go.sum`.

## 14. Key Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| D1 | Metrics server on a separate port with a synchronously created `net.Listener` | Operators can firewall port 9090 independently of port 8080. Synchronous `net.Listen` in `New()` makes `MetricsAddr()` available before `New()` returns, enabling E2E tests to scrape the correct address. |
| D2 | Dedicated `prometheus.Registry` (not global) | The global registry accumulates metrics across test instances, making counter assertions unreliable. An isolated registry per `Collector` makes every unit test deterministic. |
| D3 | `ProxyMetrics` interface in `proxy/handler.go`, not in `metrics/` | Avoids the `proxy` → `metrics` → `proxy` import cycle. The interface is defined where it is consumed; the implementation lives where it belongs. This is the standard Go cycle-breaking pattern. |
| D4 | No-op tracer when OTLP is disabled (`tracenoop.NewTracerProvider()`) | All downstream code can call `trace.SpanFromContext(ctx)` unconditionally. A nil tracer would require nil-guards everywhere. A no-op tracer is cheap and eliminates an entire class of nil-pointer bugs. |
| D5 | `otelhttp.WithSpanNameFormatter` using chi route pattern | URL paths like `/mcp/my-server/message` create one span name per unique server name, producing unbounded cardinality in trace storage. Route patterns like `/mcp/{serverName}/message` are fixed and cardinality-safe. |
| D6 | Rate limiter fails open on Redis error | Rate limiting is a capacity protection mechanism, not a security control. A Redis partition should not deny all requests. Auth failures always fail closed regardless of Redis health. |
| D7 | Sliding window (sorted set + Lua) not fixed window (INCR + TTL) | A fixed window allows a burst of `2×limit` requests spanning a window boundary (e.g., `limit` requests at 23:59:59 and `limit` more at 00:00:00). The sliding window prevents this. Lua atomicity ensures ZREMRANGEBYSCORE + ZCARD + ZADD cannot race across concurrent requests. |
| D8 | Circuit breaker per server name, not per transport instance | Multiple transport instances can be created for the same server (race on `LoadOrStore`). The circuit reflects upstream health — keying by server name is the correct scope. |
| D9 | Circuit breaker response is HTTP 200 (not 502) | The proxy's `writeError` always returns HTTP 200 per JSON-RPC semantics. Returning 502 only for circuit-open would be inconsistent with every other error response. The `Retry-After` header provides equivalent signalling for HTTP-layer clients. |
| D10 | WAL rename before read, file deleted only after confirmed write | Reduces the crash-duplicate window compared to Sprint 5's truncate-after-write. A crash before `Remove` triggers a re-replay on startup (conservative), but the unique `hash_chain` index (migration 004) will enable `ON CONFLICT DO NOTHING` idempotency in a future sprint. |
| D11 | `host(client_ip)` SQL function at the query layer (CF2) | Fixing the CIDR suffix in Go (`strings.SplitN`) is a workaround for a database behaviour. Using `host()` fixes it at the source, eliminates the strip code, and removes a subtle dependency between the Go scan logic and the Postgres `INET` type's text representation. |
| D12 | No `?token=` for WS stream auth (CF5) | URL parameters appear in server access logs, proxy logs, and browser history. Leaking a bearer token in a URL is OWASP A02. The `mcpgate_session` cookie set by the SAML ACS handler is the correct alternative and already works for browser WebSocket clients. |
| D13 | `newTestServerWith` helper instead of modifying `buildTestConfig` | Tests that need non-default config (rate limit, circuit breaker) can be self-contained. `buildTestConfig` stays as the canonical baseline for existing tests. A modifier function avoids duplicating the full config struct initialisation. |
