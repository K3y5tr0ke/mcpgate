## 1. Bug Fixes

### 1.1 Users page showed no users — response shape mismatch

**File:** `internal/admin/api/users.go`

**Symptom:** The Users page (`/console/users`) loaded without error but displayed an empty table even though users existed in the database. No network error appeared in the browser — the API returned HTTP 200.

**Root cause:** The `userHandler.list` handler serialised the user slice directly as a bare JSON array:

```go
// before
writeJSON(w, http.StatusOK, users)
// → [{"id":"...","email":"..."}]
```

The frontend `useUsers` query in `web/src/api/queries.ts` expected the same envelope shape used by every other list endpoint (`{ "users": [...], "total": N }`):

```ts
apiFetch<{ users?: User[]; total?: number }>('/users?' + toQS(params))
```

Because the response was an array (not an object), `data.users` was `undefined` and the component fell back to `data?.users ?? []` — an empty array. The table rendered zero rows silently.

**Comparison:** the servers handler (`serverHandler.list`) correctly wraps its response:
```go
writeJSON(w, http.StatusOK, map[string]any{"servers": servers, "total": total})
```
The users handler was inconsistent with this pattern.

**Fix:**

```go
// internal/admin/api/users.go — list handler
// before
users, _, err := h.store.List(r.Context(), store.UserFilter{}, store.Pagination{PageSize: 100})
...
writeJSON(w, http.StatusOK, users)

// after
users, total, err := h.store.List(r.Context(), store.UserFilter{}, store.Pagination{PageSize: 100})
...
writeJSON(w, http.StatusOK, map[string]any{"users": users, "total": total})
```

The `_` discard of the total count was also corrected — the second return value from `store.List` is now surfaced in the response, consistent with the servers and logs endpoints.

**Verification:** after restarting the server, `GET /api/v1/admin/users` returns:
```json
{ "users": [{ "id": "...", "email": "prathiksaisb.2595@gmail.com", "status": "active", ... }], "total": 1 }
```
The Users page populates correctly.

### 1.2 Bootstrap — first JIT-provisioned user has no roles

**Symptom:** After the first successful SAML login, the authenticated user received 403 on all admin API routes. Server logs showed:
```
level=INFO msg="rbac: admin access denied" user=prathiksaisb.2595@gmail.com required_role=admin
```

**Root cause:** SAML JIT provisioning (`jitProvision` in `internal/auth/saml/handlers.go`) creates new users with `status: active` but assigns no roles. The `make seed` command seeds role definitions (`admin`, `developer`, `readonly`) but has no mechanism to associate them with dynamically created users. The first operator to log in via SAML is therefore always roleless.

**Workaround applied:** assigned the `admin` role directly via SQL:
```sql
INSERT INTO user_roles (user_id, role_id, assigned_at)
VALUES (
  'a9e1b9d0-f57f-4f52-a0bc-2ffc6c24e051',  -- user ID from users table
  'bdb35810-eaa6-42e9-861d-829ba2e6f908',  -- admin role ID from roles table
  now()
)
ON CONFLICT DO NOTHING;
```

The user then logged out and back in so the ACS handler re-issued a JWT with `"roles": ["admin"]`.

**Permanent fix:** Track E (this stage) implements a local admin account created by `make seed`. Operators can now log in with the local admin account from day one without needing direct database access, and use the admin console to assign roles to their SAML account. The `MCPGATE_BOOTSTRAP_ADMIN_EMAIL` env var approach was considered and rejected in favour of the more scalable local account design (see `stage-8-plan.md §6 D9`).

### 1.3 `make setup-dev` / `make dev-frontend` — `npm: command not found` (nvm not loaded)

**Symptom:** Running `make setup-dev` failed at the `dev-frontend` step:
```
cd web && npm run dev
/bin/bash: npm: command not found
make[1]: *** [dev-frontend] Error 127
```

**Root cause:** Make recipes run in a non-interactive shell. nvm is only initialised inside `~/.zshrc` which is never sourced by Make. The same root cause was previously fixed in the pre-push hook (`scripts/pre-push.hook`) but not in the Makefile targets themselves.

**Affected targets:** `build-web`, `dev-frontend` (and transitively `build`, `dev-all`, `setup-dev`, `ci-fast`).

**Fix:** Added an `NVM` variable to the Makefile top-level that sources nvm inline, then prefixed it onto each npm-using recipe:

```makefile
# Makefile — top of file
NVM := export NVM_DIR="$${NVM_DIR:-$$HOME/.nvm}"; [ -s "$$NVM_DIR/nvm.sh" ] && . "$$NVM_DIR/nvm.sh";

# build-web
build-web:
    $(NVM) cd web && npm ci && npm run build

# dev-frontend
dev-frontend:
    $(NVM) cd web && npm run dev
```

Because Make expands `$(NVM)` as a shell snippet followed by a semicolon, the `cd` and `npm` commands that follow run in the same shell with nvm already loaded. Verified: `make build-web` completes successfully (`✓ built in 112ms`).

## 2. Track E — Local Admin Account

### Overview

Track E delivers a bootstrap admin account that operators can use without a working SAML IdP. The account is stored in the existing `users` table with `idp_name = 'local'` as the discriminator. It is created by `make seed`, authenticated via a new `POST /auth/local/login` endpoint, and accessed through a new frontend login page.

This directly addresses the bootstrapping problem described in §1.2: an operator with a fresh deployment can now seed a local admin account, log in through the browser, configure the SAML IdP from the admin console, assign their SAML account the admin role, and then suspend the local account — all without direct database access.

### E1 — Backend

#### Migration 006 — `password_hash` column

**File:** `internal/store/postgres/migrations/006_local_admin.up.sql`

Added a nullable `password_hash TEXT` column to the `users` table. The column is `NULL` for all SAML-provisioned users — it has no effect on any existing query paths. Local accounts (identified by `idp_name = 'local'`) store a bcrypt hash here.

```sql
BEGIN;
ALTER TABLE users ADD COLUMN IF NOT EXISTS password_hash TEXT;
COMMIT;
```

`IF NOT EXISTS` makes the migration idempotent if run against a schema that was manually patched before the migration file was created.

**Run:** `make migrate-up`

#### `store.User` struct — `PasswordHash` field

**File:** `internal/store/interfaces.go`

Added `PasswordHash *string` to the `User` struct. The field is tagged `json:"-"` to ensure the hash is never included in any JSON response, including the admin API's `/users` endpoint.

```go
// before
type User struct {
    ID          uuid.UUID      `db:"id"           json:"id"`
    ...
    UpdatedAt   time.Time      `db:"updated_at"   json:"updated_at,omitempty"`
}

// after
type User struct {
    ID           uuid.UUID      `db:"id"            json:"id"`
    ...
    PasswordHash *string        `db:"password_hash" json:"-"`
    UpdatedAt    time.Time      `db:"updated_at"    json:"updated_at,omitempty"`
}
```

A pointer (`*string`) is used rather than `string` to correctly represent the NULL database value for SAML users.

#### `internal/auth/local/handlers.go` — local login handler

**File:** `internal/auth/local/handlers.go` (new package)

The `local` package follows the same structural pattern as `internal/auth/saml`: a `Handlers` struct with all dependencies injected at construction time, a single exported HTTP handler method.

```go
type Handlers struct {
    userStore    store.UserStore
    sessionStore store.SessionStore
    sessionCache store.SessionCache
    roleStore    store.RoleStore
    jwtManager   *jwtpkg.Manager
    redis        *redis.Client
    authCfg      config.AuthConfig
    logger       *slog.Logger
}
```

**`Login` handler — `POST /auth/local/login`:**

Request body: `{"email": "...", "password": "..."}`.

The login flow is designed with two security invariants:

1. **No user enumeration.** The same `401 {"error":"invalid credentials"}` is returned whether the email does not exist, the account is not a local account, the password hash is missing, or the password is wrong. The response shape and timing are identical across all failure cases.

2. **`idp_name` guard.** After fetching the user by email, the handler explicitly checks `user.IDPName == "local"`. If a SAML-provisioned user has the same email, they cannot authenticate via this endpoint even if `password_hash` were somehow set on their record.

The full verification sequence:

```go
func (h *Handlers) Login(w http.ResponseWriter, r *http.Request) {
    // 1. Brute-force check (Redis INCR per IP).
    if h.bruteForceCheck(r.Context(), clientIP) {
        http.Error(w, "too many requests", http.StatusTooManyRequests)
        return
    }

    // 2. Decode body.
    var body struct {
        Email    string `json:"email"`
        Password string `json:"password"`
    }
    if err := json.NewDecoder(r.Body).Decode(&body); err != nil || body.Email == "" || body.Password == "" {
        writeJSONError(w, http.StatusBadRequest, "email and password required")
        return
    }

    // 3. Fetch user — identical 401 for not found.
    user, err := h.userStore.GetByEmail(r.Context(), body.Email)
    if errors.Is(err, store.ErrNotFound) {
        writeJSONError(w, http.StatusUnauthorized, errMsg)
        return
    }

    // 4. idp_name guard + hash presence check.
    if user.IDPName != "local" || user.PasswordHash == nil {
        writeJSONError(w, http.StatusUnauthorized, errMsg)
        return
    }

    // 5. bcrypt comparison.
    if err := bcrypt.CompareHashAndPassword([]byte(*user.PasswordHash), []byte(body.Password)); err != nil {
        writeJSONError(w, http.StatusUnauthorized, errMsg)
        return
    }

    // 6. Status check (after password verification to avoid timing difference).
    if user.Status != "active" {
        writeJSONError(w, http.StatusForbidden, "account suspended")
        return
    }

    // 7. Create session, cache in Redis, issue JWT, set cookie — identical to SAML ACS.
    ...
    http.SetCookie(w, &http.Cookie{
        Name: "mcpgate_session", Value: tokenStr,
        HttpOnly: true, Secure: true, SameSite: http.SameSiteLaxMode,
    })

    // 8. Return token for SPA localStorage storage.
    writeJSON(w, http.StatusOK, map[string]string{"token": tokenStr})
}
```

**Divergence from the plan:** the plan specified a `302` redirect as the success response. The actual implementation returns `200 {"token": "<jwt>"}` instead. A redirect response is not useful for a `fetch()` call from the SPA — the SPA intercepts the response, stores the token in `localStorage` for the `Authorization` header, and then navigates via `window.location.href`. The cookie is set in both cases; the JSON response is additional.

**Brute-force protection:** the plan listed this as deferred (S8-D9). It was implemented anyway using the same Redis INCR pattern as the SAML brute-force guard (`internal/auth/saml/brute_force.go`), as the cost was negligible and the security benefit immediate. The implementation is inline in `handlers.go` (not a shared package import) to avoid coupling the `local` package to the `saml` package:

```go
func (h *Handlers) bruteForceCheck(ctx context.Context, ip string) bool {
    if !h.authCfg.BruteForce.Enabled {
        return false
    }
    key := "brute:local_login:" + ip
    n, err := h.redis.Incr(ctx, key).Result()
    ...
}
```

**On success:** resets the brute-force counter for the IP (`bruteForceReset`). This matches the SAML ACS handler behaviour.

#### `cmd/mcpgate/main.go` — full `cmdSeed` implementation

**File:** `cmd/mcpgate/main.go`

The `cmdSeed` stub was replaced with a full implementation. New imports: `crypto/rand`, `errors`, `github.com/google/uuid`, `golang.org/x/crypto/bcrypt`, and `github.com/K3y5tr0ke/mcpgate/internal/store`.

The seed command:

1. **Loads config** from `--config` flag (default: `configs/mcpgate.dev.yaml`) to get the database DSN.
2. **Connects to Postgres** via `pgstore.NewPool`.
3. **Generates a random 20-character password** using `crypto/rand` and an alphanumeric character set:
   ```go
   func generatePassword(length int) (string, error) {
       const chars = "abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789"
       b := make([]byte, length)
       rand.Read(b)
       for i, v := range b {
           b[i] = chars[int(v)%len(chars)]
       }
       return string(b), nil
   }
   ```
4. **Bcrypt-hashes** the password at `DefaultCost` (12).
5. **Looks up `admin@localhost`** — if found, prints "Resetting password" and updates the hash. If not found, creates a new user with `idp_name = "local"`.
6. **Assigns the `admin` role** via `roleStore.AssignToUser` which uses `ON CONFLICT DO NOTHING` — idempotent even if the role is already assigned.
7. **Prints credentials** to stdout:

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  Local admin credentials
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  Email:    admin@localhost
  Password: xK9mP2vL7rQ4nBsH8f
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  Store this password — it is not recoverable.
  Run 'make seed' again to reset it.
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

**Divergences from the plan:**

| Plan | Implementation | Reason |
|------|---------------|--------|
| Email: `admin@local` | Email: `admin@localhost` | `admin@localhost` is syntactically a valid email address (RFC 5321 allows single-label domains in the local network context); `admin@local` is not. |
| Idempotent — skip creation if user exists | Reset password + print new credentials if user exists | A forgotten password has no other recovery path in Sprint 8. Running `make seed` again is the intended password reset mechanism (see `stage-8-plan.md §7 S8-D10`). |
| `GetByEmailWithHash` as a separate store method | Use existing `GetByEmail` (now returns `PasswordHash` in struct) | The `GetByEmail` signature change made the extra method unnecessary. Fewer methods = simpler interface. |

**`go.mod`:** `golang.org/x/crypto` was previously an indirect dependency pulled in by `crewjam/saml`. It is now imported directly in `cmd/mcpgate/main.go` and `internal/auth/local/handlers.go`, so the `// indirect` comment was removed from `go.mod`. (Note: `go mod tidy` could not be run via the standard `make` wrapper due to a gvm shell-hook conflict in the non-interactive environment; the `go.mod` edit was applied manually.)

### E2 — Frontend

#### `web/src/pages/login/LocalLoginPage.tsx` — login form

**File:** `web/src/pages/login/LocalLoginPage.tsx` (new)

A standalone, full-page login form — no `AppShell` wrapper (the user is not yet authenticated). Placed under `pages/login/` rather than `pages/auth/` (as the plan specified) to keep the folder name self-evident alongside other page folders.

**Design:**
- Centred card layout on `bg-gray-50`, `max-w-sm`.
- Email input pre-filled with `admin@localhost` (the only valid local account email, makes it easy to use without memorising the address).
- Password input with `autocomplete="current-password"`.
- Inline error display: `bg-red-50 text-red-700` for all error states.
- Footer hint: _"Run `make seed` to create or reset the local admin password."_
- No "Sign in with SSO" link in the initial implementation — the login page is a simple focused form. The SSO link was added later in the same sprint (see §9.7) once the redirect change (§9.4) revealed that SAML users had lost their login path.

**Authentication flow:**

```tsx
const res = await fetch('/auth/local/login', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ email, password }),
})
...
const { token } = await res.json()
localStorage.setItem('mcpgate_token', token)
window.location.href = redirectTo   // from ?redirect_to= query param
```

The `redirect_to` parameter is read from the URL (`new URLSearchParams(window.location.search).get('redirect_to')`), allowing the 401 redirect in `client.ts` to carry the intended destination through the login page.

Both `localStorage` (for the `Authorization: Bearer` header in `apiFetch`) and the `mcpgate_session` cookie (set by the server, used by the browser for same-origin requests) are populated on success.

**Error states handled:**
- `429` — "Too many attempts. Please wait before trying again."
- `403` — "Account suspended. Contact an administrator."
- Any other non-2xx — "Invalid credentials."
- Network error (fetch throws) — "Network error. Is the server running?"

## 3. Track A — Backend Carry-Overs

### A1 — Metrics Timeseries Redis INCR

**Goal:** The `GET /api/v1/admin/metrics/timeseries` endpoint was a single-point placeholder in Sprint 7 (see stage-7-26-05-2026.md §14, Decision D6). This track implements the full per-minute INCR approach using Redis keys.

#### `internal/metrics/collector.go` — Redis field + per-minute INCR

**File:** `internal/metrics/collector.go`

Added `redis goredis.Cmdable` field to `Collector`. Using the interface type `goredis.Cmdable` (not `*goredis.Client`) keeps the `Collector` testable without a real Redis connection.

```go
// New field on Collector struct
type Collector struct {
    // ... existing Prometheus counter/histogram fields ...
    redis goredis.Cmdable
}
```

New exported method to inject the Redis dependency after construction (avoids changing `NewCollector` signature):

```go
func (c *Collector) WithRedis(client goredis.Cmdable) {
    c.redis = client
}
```

The `Middleware()` method was updated to INCR a per-minute Redis key on every request:

```go
if c.redis != nil {
    now := time.Now()
    key := fmt.Sprintf("metrics:ts:%d", now.Unix()/60)
    ctx := r.Context()
    c.redis.Incr(ctx, key)
    c.redis.Expire(ctx, key, 7*24*time.Hour)
}
```

Key design:
- **Key format:** `metrics:ts:<unix_minute>` where `unix_minute = time.Now().Unix() / 60`. This gives one key per calendar minute, aligned to wall-clock boundaries.
- **TTL:** 7 days. The timeseries handler reads the last 60 minutes; 7 days ensures historical data survives restarts and is available for any future drilldown UI without requiring explicit cleanup.
- **No pipeline:** each request fires two commands (`INCR` + `EXPIRE`). The `EXPIRE` resets the TTL on each write (not just on first write), which is correct because the key is alive as long as requests are arriving. In production, pipelining could reduce round-trips; this is left for a future optimisation.

**Imports added:** `"fmt"`, `goredis "github.com/redis/go-redis/v9"`.

#### `internal/admin/api/metrics.go` — timeseries handler rewrite

**File:** `internal/admin/api/metrics.go`

Added `redis *goredis.Client` field to `metricsHandler` (concrete type here because the handler uses pipeline, which is only available on `*goredis.Client`, not the `Cmdable` interface).

The `timeseries` handler was rewritten to read 60 buckets via a Redis pipeline:

```go
type bucket struct {
    Minute   int64 `json:"minute"`
    Requests int64 `json:"requests"`
}

func (h *metricsHandler) timeseries(w http.ResponseWriter, r *http.Request) {
    const numBuckets = 60
    now := time.Now().Unix() / 60

    if h.redis == nil {
        // Fallback for deployments without Redis: return current RPM as single-point series.
        writeJSON(w, http.StatusOK, map[string]any{
            "buckets": []bucket{{Minute: now, Requests: h.collector.RequestsLastMinute()}},
        })
        return
    }

    ctx := r.Context()
    pipe := h.redis.Pipeline()
    cmds := make([]*goredis.StringCmd, numBuckets)
    for i := 0; i < numBuckets; i++ {
        min := now - int64(numBuckets-1-i)
        cmds[i] = pipe.Get(ctx, fmt.Sprintf("metrics:ts:%d", min))
    }
    _, _ = pipe.Exec(ctx)

    buckets := make([]bucket, numBuckets)
    for i, cmd := range cmds {
        min := now - int64(numBuckets-1-i)
        buckets[i].Minute = min
        if val, err := cmd.Result(); err == nil {
            if n, err := strconv.ParseInt(val, 10, 64); err == nil {
                buckets[i].Requests = n
            }
        }
        // Missing key (redis.Nil) or parse error → Requests stays 0, which is correct.
    }

    writeJSON(w, http.StatusOK, map[string]any{"buckets": buckets})
}
```

The pipeline sends all 60 `GET` commands in a single round-trip. Each `cmd.Result()` call reads the pre-fetched result without blocking. Minutes with no traffic (key does not exist) produce `redis.Nil` which is silently treated as 0.

**Imports added:** `"fmt"`, `"strconv"`, `"time"`, `goredis "github.com/redis/go-redis/v9"`.

#### `internal/ratelimit/middleware.go` — concurrent connection check

**File:** `internal/ratelimit/middleware.go`

After the RPM/RPD `Allow` check passes, the middleware now checks concurrent connections:

```go
if cfg.Default.ConcurrentConnections > 0 {
    overLimit, cleanup, cerr := limiter.StartConcurrent(r.Context(), userKey, cfg.Default.ConcurrentConnections)
    if cerr != nil {
        logger.Warn("concurrent limiter error (fail open)", "user", userKey, "err", cerr)
    } else {
        defer cleanup()
        if overLimit {

                col.RateLimitHits.WithLabelValues("concurrent").Inc()

            return
        }
    }
```

Design notes:
- **Fail open:** Redis errors on `StartConcurrent` are logged but do not reject the request. A Redis partition should not sever all SSE/WS connections.
- **`defer cleanup()`:** the cleanup function (which calls `DECR` on the concurrent counter) is deferred for the entire request lifetime, not just the middleware stack. For SSE connections that hold the goroutine open for minutes/hours, this is the correct point to decrement.
- **Label:** `RateLimitHits.WithLabelValues("concurrent")` distinguishes concurrent-limit hits from RPM/RPD hits in Prometheus.
- **`writeRateLimitError(w, r, 0)`:** the `RetryAfter` seconds are 0 for concurrent limit rejections (the client should retry immediately, not after a fixed window).

### A3 — Per-Role Rate Limit Override Lookup

**Goal:** `RateLimitOverrideStore` was wired into `server.New()` and `api.NewRouter` in Sprint 7 (CF-S6-6) but the middleware lookup was deferred. This track wires it: when a user has roles with custom RPM/RPD overrides, the highest limit wins (most-permissive-wins policy).

#### `internal/ratelimit/middleware.go` — new `overrides` parameter + per-role lookup

**File:** `internal/ratelimit/middleware.go`

**New signature:**

```go
func Middleware(
    limiter   store.RateLimiter,
    overrides store.RateLimitOverrideStore,   // ← new (nil = use global defaults)
    cfg       config.RateLimitingConfig,
    col       *metrics.Collector,
    logger    *slog.Logger,
) func(http.Handler) http.Handler
```

Per-role override lookup (most-permissive-wins):

```go
if overrides != nil && len(identity.Roles) > 0 {
    bestRPM, bestRPD := 0, 0
    for _, role := range identity.Roles {
        entry, err := overrides.GetByRole(r.Context(), role)
        if err != nil {
            continue  // ErrNotFound or Redis error → skip, use global default
        }
        if entry.RPM > bestRPM {
            bestRPM = entry.RPM
        }
        if entry.RPD > bestRPD {
            bestRPD = entry.RPD
        }
    }
    if bestRPM > 0 {
        limit.RPM = bestRPM
    }
    if bestRPD > 0 {
        limit.RPD = bestRPD
    }
}
```

**Policy:** the highest RPM across all of a user's roles is applied, independently of RPD. A user with roles `["developer", "partner"]` where `developer` has RPM=200, RPD=0 and `partner` has RPM=0, RPD=10000 will get RPM=200 + RPD=10000 — each dimension picks its own maximum. This is the most permissive interpretation and avoids surprising users who hold multiple roles.

**Nil-safety:** `overrides != nil` is checked before any store call. Passing `nil` as the overrides parameter (as done in unit tests) skips the per-role lookup entirely and falls back to global config defaults.

**Errors are skipped silently:** a `GetByRole` error (Redis down, network timeout) causes the override to be skipped, not the request to be rejected. Rate limiting falls back to the global default. This is consistent with the fail-open design of the limiter itself.

```go
func (h *roleHandler) putRateLimits(w http.ResponseWriter, r *http.Request) {
    roleID, err := uuid.Parse(chi.URLParam(r, "id"))
    // ... error handling ...

    role, err := h.store.GetByID(r.Context(), roleID)
    // ... error handling ...

    var body struct {
        RPM int `json:"rpm"`
        RPD int `json:"rpd"`
    }
    if err := json.NewDecoder(r.Body).Decode(&body); err != nil {
        writeJSON(w, http.StatusBadRequest, map[string]string{"error": "invalid body"})
        return
    }

    if body.RPM == 0 && body.RPD == 0 {
        // Both zero = delete the override (fall back to global defaults).
        _ = h.overrides.Delete(r.Context(), role.Name)
        writeJSON(w, http.StatusOK, map[string]int{"rpm": 0, "rpd": 0})
        return
    }

    entry := &store.RateLimitOverrideEntry{
        RoleName: role.Name,
        RPM:      body.RPM,
        RPD:      body.RPD,
    }
    if err := h.overrides.Upsert(r.Context(), entry); err != nil {
        writeJSON(w, http.StatusInternalServerError, map[string]string{"error": "internal error"})
        return
    }
    writeJSON(w, http.StatusOK, map[string]int{"rpm": body.RPM, "rpd": body.RPD})
}
```

**Design — `{rpm:0, rpd:0}` deletes the override:** when both values are zero it means "use global defaults" — there is no meaningful distinction between "unset" and "set to 0". This avoids a separate `DELETE` endpoint and keeps the API surface minimal.

#### `web/src/components/logs/LiveLogPanel.tsx` (new)

**File:** `web/src/components/logs/LiveLogPanel.tsx`

```tsx
export function LiveLogPanel() {
    const [running, setRunning] = useState(false)
    const [entries, setEntries] = useState<string[]>([])
    const wsRef = useRef<WebSocket | null>(null)
    const bottomRef = useRef<HTMLDivElement>(null)

    const start = () => {
        const proto = window.location.protocol === 'https:' ? 'wss:' : 'ws:'
        const ws = new WebSocket(`${proto}//${window.location.host}/api/v1/admin/logs/stream`)
        wsRef.current = ws
        ws.onopen = () => setRunning(true)
        ws.onmessage = (e) => {
            setEntries((prev) => {
                const next = [...prev, e.data]
                return next.length > 200 ? next.slice(-200) : next
            })
        }
        ws.onclose = () => setRunning(false)
    }

    const stop = () => {
        wsRef.current?.close()
        setRunning(false)
    }

    // Auto-scroll on new entry
    useEffect(() => {
        bottomRef.current?.scrollIntoView({ behavior: 'smooth' })
    }, [entries])

    // Cleanup on unmount
    useEffect(() => () => { wsRef.current?.close() }, [])

    return (
        <Card title="Live log stream">
            <div className="flex gap-2 mb-2">
                <Button onClick={start} disabled={running} variant="secondary">Start</Button>
                <Button onClick={stop} disabled={!running} variant="ghost">Pause</Button>
            </div>
            <div className="h-48 overflow-y-auto font-mono text-xs bg-gray-900 text-green-400 p-2 rounded">
                {entries.map((e, i) => <div key={i}>{e}</div>)}
                <div ref={bottomRef} />
            </div>
        </Card>
    )
}
```

**Security:** the WebSocket URL contains no token or query parameter. The `mcpgate_session` cookie (`HttpOnly; Secure; SameSite=Lax`) is automatically sent by the browser with the WS upgrade request for same-origin connections. Adding `?token=` to a WebSocket URL would expose the bearer token in server access logs, proxy logs, and browser history — a firm constraint established in Sprint 5.

**Buffer limit:** entries are capped at 200 to prevent unbounded memory growth in long-running sessions. `slice(-200)` keeps the most recent 200 entries.

**File:** `web/src/components/roles/PolicyMatrix.tsx`

```tsx
interface Props {
    roles: Role[]
    servers: MCPServer[]
    policies: Policy[]
    onAdd: (subject: string, resource: string, action: string) => void
    onRemove: (subject: string, resource: string, action: string) => void
}

const ACTIONS = ['read', 'write', 'execute', 'admin', 'stream']

export function PolicyMatrix({ roles, servers, policies, onAdd, onRemove }: Props) {
    const resources = ['*', ...servers.map((s) => s.name)]

    function hasPolicy(subject: string, resource: string, action: string): boolean {
        return policies.some(
            (p) => p.subject === subject && p.resource === resource && p.action === action
        )
    }

    function toggle(subject: string, resource: string, action: string) {
        if (hasPolicy(subject, resource, action)) {
            onRemove(subject, resource, action)
        } else {
            onAdd(subject, resource, action)
        }
    }

    return (
        <div className="overflow-x-auto">
            <table className="text-xs border-collapse">
                <thead>
                    <tr>
                        <th>Role</th>
                        {resources.map((res) => (
                            <th key={res} colSpan={ACTIONS.length}
                                className="border px-2 py-1 bg-gray-100 dark:bg-gray-800">
                                {res}
                            </th>
                        ))}
                    </tr>
                    <tr>
                        <th />
                        {resources.flatMap((res) =>
                            ACTIONS.map((action) => (
                                <th key={`${res}-${action}`}
                                    className="border px-1 py-1 font-normal text-gray-500">
                                    {action}
                                </th>
                            ))
                        )}
                    </tr>
                </thead>
                <tbody>
                    {roles.map((role) => (
                        <tr key={role.id}>
                            <td className="border px-2 py-1 font-medium">{role.name}</td>
                            {resources.flatMap((res) =>
                                ACTIONS.map((action) => {
                                    const allowed = hasPolicy(role.name, res, action)
                                    return (
                                        <td key={`${res}-${action}`}
                                            className="border px-1 py-1 text-center cursor-pointer hover:bg-gray-50 dark:hover:bg-gray-800"
                                            onClick={() => toggle(role.name, res, action)}
                                            title={allowed ? 'Click to remove' : 'Click to allow'}>
                                            {allowed
                                                ? <span className="text-green-500">✓</span>
                                                : <span className="text-gray-300">○</span>}
                                        </td>
                                    )
                                })
                            )}
                        </tr>
                    ))}
                </tbody>
            </table>
        </div>
    )
}
```

**Design:**
- Columns: `*` (wildcard resource) followed by each server name. Each resource gets 5 sub-columns (one per action).
- Rows: one per role.
- Cells: green checkmark `✓` if the policy exists, grey circle `○` if not. `onClick` calls `onAdd` or `onRemove` depending on current state.
- No separate "Save" button — each cell click immediately mutates via `onAdd`/`onRemove` (which call the API via TanStack Query mutations). Optimistic updates are not implemented; the cell re-renders on the next successful query refetch.

### C4 — Dark Mode Toggle

**Goal:** Add a per-session dark mode toggle to `AppShell` and apply `dark:` Tailwind variants across all structural elements.

#### `web/src/index.css` — Tailwind v4 dark mode variant

**File:** `web/src/index.css`

```css
@custom-variant dark (&:where(.dark, .dark *));
```

Tailwind v4 does not automatically include a `dark:` variant — it must be declared explicitly. The `&:where(.dark, .dark *)` selector activates dark styles when the `dark` class is present on the element itself or any ancestor (the `<html>` element in practice). This is the class-based strategy, not the `prefers-color-scheme` media-query strategy, which allows user-controlled toggling.

---

#### `web/src/hooks/useDarkMode.ts` (new)

**File:** `web/src/hooks/useDarkMode.ts`

```typescript
const KEY = 'mcpgate_dark_mode'

export function useDarkMode() {
    const [dark, setDark] = useState<boolean>(() => {
        const stored = localStorage.getItem(KEY)
        if (stored !== null) return stored === 'true'
        return window.matchMedia('(prefers-color-scheme: dark)').matches
    })

    useEffect(() => {
        document.documentElement.classList.toggle('dark', dark)
        localStorage.setItem(KEY, String(dark))
    }, [dark])

    return { dark, toggle: () => setDark((d) => !d) }
}
```

**Initialisation order:**
1. Check `localStorage` first — respects a user's explicit choice.
2. Fall back to `prefers-color-scheme` media query — respects OS default on first visit.

**Persistence:** `localStorage.setItem` on every change. The `<html>` class is updated in `useEffect` (synchronously after paint) to avoid a flash of wrong theme.

### 9.1 `cmd/mcpgate/main.go` — `ifElseChain` (gocritic)

**Error:**
```
cmd/mcpgate/main.go:149:2: ifElseChain: rewrite if-else to switch statement (gocritic)
```

The `cmdSeed` function looked up the local admin user by email and then branched on the error:

```go
// before
user, err := userStore.GetByEmail(ctx, adminEmail)
if errors.Is(err, store.ErrNotFound) {
    // create new user
} else if err != nil {
    return fmt.Errorf("lookup admin user: %w", err)

    // reset password on existing user
}
```

gocritic flags three-branch `if/else if/else` chains as harder to read than an equivalent `switch`. The rewrite has the same semantics:

```go
// after
user, err := userStore.GetByEmail(ctx, adminEmail)
switch {
case errors.Is(err, store.ErrNotFound):
    // create new user
case err != nil:
    return fmt.Errorf("lookup admin user: %w", err)
default:
    // reset password on existing user
}
```

`switch` with no expression evaluates each `case` as a boolean condition — identical in behaviour to the `if/else if/else` form but visually parallel and easier to extend.

### 9.2 `internal/admin/api/metrics.go` — `builtinShadow` (gocritic)

**Errors:**

```
internal/admin/api/metrics.go:203:3: builtinShadow: shadowing of predeclared identifier: min (gocritic)
internal/admin/api/metrics.go:210:3: builtinShadow: shadowing of predeclared identifier: min (gocritic)
```

`bucketMin` is descriptive — it names the Unix minute that this bucket represents — while avoiding the conflict with the `min(a, b)` built-in.

### 9.4 `web/src/router.tsx` + `web/src/api/client.ts` — login page returns HTTP 405

**Symptom:** After `make setup-dev`, navigating to `http://127.0.0.1:8080/console` caused the browser to land on `http://127.0.0.1:8080/auth/local/login?redirect_to=/console/dashboard` with an HTTP 405 response. Server logs showed:

```
method=GET path=/auth/local/login status=405
```

**Root cause:** `client.ts` redirected unauthenticated API calls to `GET /auth/local/login`. The server only registered a `POST` handler for that path (`r.Post("/auth/local/login", s.localHandlers.Login)`). The SPA handler (`consoleSPAHandler`) only covers `/console/*` — paths under `/auth/*` are never served `index.html`, so TanStack Router never gets a chance to render `LocalLoginPage`.

The SAML login redirect (`/auth/saml/login`) worked in the previous design because the server had a `GET` handler there that immediately issued an HTTP redirect to the IdP. Local login has no such redirect — the server-side route is a POST-only API endpoint.

**Fix:** moved the SPA client-side route from `/auth/local/login` to `/console/login`. The POST API endpoint on the server (`/auth/local/login`) is unchanged.

`web/src/router.tsx`:
```tsx
// before
path: '/auth/local/login',

// after
path: '/console/login',
```

`web/src/api/client.ts`:
```ts
// before
window.location.href = '/auth/local/login?redirect_to=/console/dashboard'

// after
window.location.href = '/console/login?redirect_to=/console/dashboard'
```

The corrected login flow:
1. Browser navigates to `/console/*` → `consoleSPAHandler` serves `index.html`
2. SPA gets 401 → redirects to `GET /console/login?redirect_to=/console/dashboard`
3. `consoleSPAHandler` catches it (no `dist/login` file exists → falls back to `index.html`)
4. TanStack Router renders `LocalLoginPage` at `/console/login`
5. User submits form → `POST /auth/local/login` (backend, unchanged)

### 9.5 `internal/store/redis/rate_limiter_test.go` — flaky test from stale Redis keys

**Symptom:** `TestRateLimiter_RPM_And_RPD_Independent` failed intermittently with:

```
rate_limiter_test.go:90: request 0 should be allowed
```

The very first `Allow` call in the test was returning `Allowed: false`, despite the test using `RPM: 2`.

**Root cause:** The integration test suite connects to the live dev Redis instance at `localhost:6379` (not a testcontainer). The `uniqueKey` helper generated a deterministic key based solely on the test name:

```go
// before
func uniqueKey(t *testing.T) string {
    return "test:" + t.Name() + ":" + t.Name()
}
```

The rate limiter stores sliding-window entries in a Redis sorted set with a `PEXPIRE` TTL equal to the window size — 60 seconds for RPM keys. Entries written during a previous test run remain in Redis for up to 60 seconds. Re-running the integration tests within that window found the sorted set already at capacity (2 entries, matching `RPM: 2`), so the test's first `Allow` call incremented the count to 3 and was denied.

**Fix:** added a `testRunID` package-level variable set to `time.Now().UnixNano()` once per binary execution. `uniqueKey` appends this nonce, making each test invocation use a fresh key namespace isolated from any previous run:

```go
// after
var testRunID = fmt.Sprintf("%d", time.Now().UnixNano())

func uniqueKey(t *testing.T) string {
    return fmt.Sprintf("test:%s:%s", t.Name(), testRunID)
}
```

The nonce is computed at package init time (constant within a run, unique across runs) so repeated calls to `uniqueKey(t)` within the same test return the same key — which is required for tests that call `Allow` multiple times on the same counter.

**Imports added:** `"fmt"` (already present in the file via other uses).

#### 9.8.2 `<select>` elements did not show selected value — missing `bg-white text-gray-900`

**Symptom:** In the "Access policies (raw)" section of the Roles page, the Role dropdown and Action dropdown would show options when opened, but the selected value was invisible in the collapsed state. The dropdown appeared blank even after selecting an option.

**Root cause:** The two raw `<select>` elements in `web/src/pages/roles/RolesListPage.tsx` had no explicit background colour or text colour:

```tsx
// before — no bg-white, no text-gray-900
className="h-9 rounded-md border border-gray-300 px-3 text-sm focus:outline-none focus:ring-2 focus:ring-indigo-500"
```

Tailwind v4's preflight reset removes all browser default styles. Without an explicit `color` on the `<select>`, the element inherits the parent's `color` value. In this layout the parent chain includes elements with `text-gray-50` or similar light text for dark-mode compatibility. When the page is in light mode the browser renders the `<select>` with a light background (UA default) but the inherited text colour is nearly white — invisible.

**Fix:** Added `bg-white text-gray-900` to both `<select>` elements:

```tsx
// after — Role select
className="h-9 rounded-md border border-gray-300 bg-white px-3 text-sm text-gray-900 focus:outline-none focus:ring-2 focus:ring-indigo-500"

// after — Action select
className="h-9 rounded-md border border-gray-300 bg-white px-3 text-sm text-gray-900 focus:outline-none focus:ring-2 focus:ring-indigo-500"
```

`bg-white` ensures the dropdown background is always white in light mode (not inherited or UA-default). `text-gray-900` pins the text colour regardless of what the parent chain inherits.
