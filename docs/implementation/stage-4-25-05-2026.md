## 1. What Was Implemented

Sprint 4 closes the authorisation gap: every authenticated request to the MCP proxy now requires an explicit Casbin policy rule to proceed. The admin REST API is locked to the `admin` role. Authenticated principals with no matching policy receive 403.

- **Casbin v2 RBAC enforcer** (`internal/auth/rbac/enforcer.go`) backed by PostgreSQL via the `pckhoi/casbin-pgx-adapter/v3` adapter. The model is `sub, obj, act` (role, MCP server name, action). Policy rules are stored in `casbin_rule` in Postgres and cached in Redis per decision.
- **Migration 003** (`003_rbac_seed`) drops and recreates `casbin_rule` to match the adapter's expected schema (column `p_type`, `id TEXT` as meow hash), then seeds three system roles (`admin`, `developer`, `readonly`) and calls `SeedDefaultPolicies()` at server startup to insert the admin wildcard rule (`p, admin, *, *`).
- **Redis `PolicyCache`** (`internal/store/redis/policy_cache.go`) — per-decision cache keyed as `rbac:<role>:<server>:<action>`; SCAN+DEL batches for invalidation after any policy mutation.
- **`RoleStore` completion** (`internal/store/postgres/roles.go`) — all eight stubs fully implemented: `Create`, `GetByID`, `GetByName`, `List`, `Update`, `Delete`, `AssignToUser`, `RevokeFromUser`. `Delete` reads the role first and returns `store.ErrConflict` for system roles.
- **`Authorize` middleware** (`internal/auth/rbac/middleware.go`) — `GET` requests (SSE stream open) are enforced under action `"connect"`; `POST` requests buffer the body, call `proxy.Parse()` + `proxy.Action()` to map the JSON-RPC method to an action string, then restore the body for the proxy handler.
- **`RequireRole("admin")` middleware** — a simple slice scan on `UserIdentity.Roles` applied to the admin API group. Does not go through Casbin.
- **Admin REST API additions**: `policies.go` (Casbin policy CRUD), `roles.go` (role CRUD + user assignment), `users.go` (user list/get/patch-status). `router.go` updated with new route groups and expanded `NewRouter` signature.
- **`GET /api/v1/me` identity endpoint** — auth-only (no role required), returns `user_id`, `email`, `roles`, `session_id` from context. Added to fix test regressions caused by wiring `RequireRole("admin")` to the admin group (see §11).
- **E2E test suite** (`tests/e2e/rbac_test.go`) — 8 new integration tests covering the admin wildcard policy, 403 on no matching policy, developer allow/deny, readonly list-vs-call, cross-server isolation, cache invalidation, and admin API role guard.

## 3. Migration 003 — `casbin_rule` Rebuild and Role Seed

**`internal/store/postgres/migrations/003_rbac_seed.up.sql`:**

```sql
BEGIN;

-- Rebuild casbin_rule to match pckhoi/casbin-pgx-adapter/v3 schema.
-- Migration 001 used id BIGSERIAL and column "ptype"; the adapter expects
-- id TEXT (meow hash) and column "p_type". The table is empty in all
-- environments prior to Sprint 4 so the DROP is safe.
DROP TABLE casbin_rule;

CREATE TABLE casbin_rule (
    id     TEXT PRIMARY KEY,
    p_type TEXT,
    v0     TEXT,
    v1     TEXT,
    v2     TEXT,
    v3     TEXT,
    v4     TEXT,
    v5     TEXT
);

CREATE INDEX idx_casbin_rule_ptype ON casbin_rule (p_type);

-- Seed system roles. is_system = true prevents deletion via the admin API.
INSERT INTO roles (id, name, description, is_system)
VALUES
    (gen_random_uuid(), 'admin',     'Full access to all MCP servers and admin API', true),
    (gen_random_uuid(), 'developer', 'Read and call access to allowed servers',       true),
    (gen_random_uuid(), 'readonly',  'List and read access only',                     true)
ON CONFLICT (name) DO NOTHING;

-- Note: the default admin wildcard policy (p, admin, *, *) is seeded at
-- application startup via enforcer.SeedDefaultPolicies() because the row ID
-- is computed as a meow hash by the adapter and cannot be predicted in SQL.

COMMIT;
```

**`internal/store/postgres/migrations/003_rbac_seed.down.sql`:**

```sql
BEGIN;

DELETE FROM roles WHERE name IN ('admin', 'developer', 'readonly') AND is_system = true;

DROP INDEX  IF EXISTS idx_casbin_rule_ptype;
DROP TABLE  casbin_rule;

-- Restore the original schema from migration 001.
CREATE TABLE casbin_rule (
    id    BIGSERIAL PRIMARY KEY,
    ptype TEXT      NOT NULL,
    v0    TEXT      NOT NULL DEFAULT '',
    v1    TEXT      NOT NULL DEFAULT '',
    v2    TEXT      NOT NULL DEFAULT '',
    v3    TEXT      NOT NULL DEFAULT '',
    v4    TEXT      NOT NULL DEFAULT '',
    v5    TEXT      NOT NULL DEFAULT ''
);
CREATE INDEX idx_casbin_rule_ptype ON casbin_rule (ptype);

-- Note: down migration restores the original schema; the adapter will not work
-- with this schema — run migrate-up again to re-enable RBAC.

COMMIT;
```

**Key schema decisions:**

- All value columns (`v0`–`v5`) are plain `TEXT` (nullable). The plan originally specified `NOT NULL DEFAULT ''`, but the adapter passes `NULL` for unused columns in a 3-part policy rule (`p, admin, *, *`). The `NOT NULL DEFAULT ''` constraint caused an integration test failure with `null value in column "v3" violates not-null constraint`. The final schema matches the adapter's own DDL exactly (nullable columns, no defaults).
- The admin wildcard policy row cannot be seeded via SQL because its `id` is computed by the adapter as a meow hash of the rule string. `SeedDefaultPolicies()` in `server.New()` calls `e.e.AddPolicy("admin", "*", "*")` — Casbin is idempotent: it returns `false` (not an error) when the rule already exists.

## 4. Store Layer

### 4.1 `ErrConflict` (`internal/store/errors.go`)

```go
var ErrConflict = errors.New("store: operation conflicts with existing state")
```

Added alongside the existing `ErrNotFound` and `ErrAlreadyExists`. Used by `RoleStore.Delete` to signal that a system role cannot be deleted.

### 4.2 `PolicyCache` (`internal/store/redis/policy_cache.go`)

```go
type PolicyCache struct{ client *goredis.Client }

func NewPolicyCache(client *goredis.Client) *PolicyCache

// Get returns nil, nil on cache miss. *true = allow, *false = deny.
func (c *PolicyCache) Get(ctx context.Context, key string) (*bool, error)

func (c *PolicyCache) Set(ctx context.Context, key string, allowed bool, ttl time.Duration) error

// Invalidate deletes all keys matching the glob pattern via SCAN+DEL batches (100 keys/batch).
func (c *PolicyCache) Invalidate(ctx context.Context, pattern string) error
```

Cache key format: `rbac:<role>:<serverName>:<action>` — e.g. `rbac:developer:my-server:call`.

`Get` returns `nil, nil` on a Redis miss (not `store.ErrNotFound`) to distinguish "not cached" from "cached deny". The caller pattern is:

```go
if cached, err := e.cache.Get(ctx, key); err == nil && cached != nil {
    // use *cached
}
// cache miss: evaluate Casbin
```

`Invalidate` uses a SCAN cursor loop to handle key spaces larger than a single DEL can address atomically. Batch size is 100. Called synchronously after every policy mutation — correctness over cache efficiency (see Key Decisions §D7).

### 4.3 `RoleStore` Completion (`internal/store/postgres/roles.go`)

All eight methods fully implemented. Follows the same pgx scan helper pattern as `users.go`:

```go
type roleScanner interface{ Scan(dest ...any) error }

func scanRole(row pgx.Row) (*store.Role, error)
func scanRoleRow(row roleScanner) (*store.Role, error)
```

| Method | Behaviour |
|--------|-----------|
| `Create` | `RETURNING id, created_at`; unique violation on `name` → `ErrAlreadyExists` |
| `GetByID` | Single row; `ErrNoRows` → `ErrNotFound` |
| `GetByName` | Single row; `ErrNoRows` → `ErrNotFound` |
| `List` | `ORDER BY name` |
| `Update` | Full replace (`name`, `description`); `RowsAffected == 0` → `ErrNotFound`; unique violation → `ErrAlreadyExists` |
| `Delete` | Reads role first → `ErrConflict` if `is_system = true`; then `DELETE`; `RowsAffected == 0` → `ErrNotFound` |
| `AssignToUser` | `INSERT ... ON CONFLICT DO NOTHING` (idempotent) |
| `RevokeFromUser` | `DELETE FROM user_roles WHERE user_id = $1 AND role_id = $2`; `RowsAffected == 0` → `ErrNotFound` |
| `GetUserRoles` | `JOIN user_roles ON role_id` filtered by `user_id`, `ORDER BY name` — unchanged from Sprint 2 stub |

`Delete` reads the role via `GetByID` before deleting. This is a deliberate two-query design: the system role check must happen inside the same Go function (not a DB trigger) so that the error can be mapped to `store.ErrConflict` and surfaced as HTTP 409 by the handler.

## 5. RBAC Enforcer (`internal/auth/rbac/enforcer.go`)

### 5.1 Casbin Model

```
[request_definition]
r = sub, obj, act

[policy_definition]
p = sub, obj, act

[policy_effect]
e = some(where (p.eft == allow))

[matchers]
m = r.sub == p.sub && (p.obj == "*" || r.obj == p.obj) && (p.act == "*" || r.act == p.act)
```

`sub` = role name, `obj` = MCP server name (or `"*"`), `act` = action category. Wildcards in stored rules match any value in the request — so `p, admin, *, *` covers every server and action for the admin role.

### 5.2 Adapter Initialisation

```go
adapter, err := pgxadapter.NewAdapter(
    nil,
    pgxadapter.WithConnectionPool(db),
    pgxadapter.WithSkipTableCreate(),
)
```

`nil` is passed as the first argument (connection string) — it is ignored when `WithConnectionPool` is provided. `WithSkipTableCreate()` prevents the adapter from auto-creating its own table; the schema is owned entirely by migration 003.

The first argument type was discovered by reading the adapter source at `$(go env GOPATH)/pkg/mod/github.com/pckhoi/casbin-pgx-adapter/v3@v3.2.0/adapter.go`. The public function signature accepts `conn *pgx.Conn` as position 1; passing `nil` is valid and harmless when a pool is supplied.

### 5.3 `SeedDefaultPolicies`

```go
func (e *Enforcer) SeedDefaultPolicies(ctx context.Context) error {
    if _, err := e.e.AddPolicy("admin", "*", "*"); err != nil {
        return fmt.Errorf("rbac: seed admin policy: %w", err)
    }
    return nil
}
```

Called from `server.New()` on every startup. `e.e.AddPolicy` returns `(bool, error)` — the bool is `false` when the policy already exists (not inserted) and `true` when newly added. The bool is discarded; neither `false` nor `true` is an error. This makes the call unconditionally idempotent.

### 5.4 `Enforce` — Cache-First Loop

```go
func (e *Enforcer) Enforce(ctx context.Context, roles []string, serverName, action string) (bool, error) {
    for _, role := range roles {
        key := fmt.Sprintf("rbac:%s:%s:%s", role, serverName, action)

        if cached, err := e.cache.Get(ctx, key); err == nil && cached != nil {
            if *cached {
                return true, nil
            }
            continue
        }

        allowed, err := e.e.Enforce(role, serverName, action)
        if err != nil {
            return false, fmt.Errorf("rbac: enforce: %w", err)
        }

        if cacheErr := e.cache.Set(ctx, key, allowed, e.cacheTTL); cacheErr != nil {
            e.logger.Warn("rbac: policy cache set failed", "err", cacheErr)
        }

        if allowed {
            return true, nil
        }
    }
    return false, nil
}
```

Short-circuits on first allow. Cache set failures are logged as warnings (cache availability must not gate auth decisions). On `Enforce` error, the error propagates to the middleware which falls back to `DefaultAllow()`.

### 5.5 Policy CRUD

`AddPolicy` and `RemovePolicy` delegate to the Casbin enforcer and then call `ReloadPolicy`. `ReloadPolicy` calls `e.e.LoadPolicy()` (reads from Postgres) and `e.cache.Invalidate(ctx, "rbac:*")`. Invalidation is synchronous — stale cached allow/deny decisions are a security risk; cache performance is a secondary concern.

`ListPolicies` calls `e.e.GetPolicy()`. The Casbin v2 API returns `([][]string, error)` — the error return was introduced in v2 but is always `nil` for in-memory policy reads. The underscore discard pattern `rules, _ := e.e.GetPolicy()` was required after a compile error revealed that the return was two-valued (the plan's pseudocode showed one-valued).

## 6. RBAC Middleware (`internal/auth/rbac/middleware.go`)

### 6.1 `Authorize`

```go
func Authorize(enforcer *Enforcer, logger *slog.Logger) func(http.Handler) http.Handler
```

Applied to the `/mcp/{serverName}` route group after `authMiddleware`. Execution flow:

1. `auth.MustIdentity(r.Context())` — panics if identity absent (upstream auth middleware guarantees it)
2. `chi.URLParam(r, "serverName")` — extracted from the path
3. **Action resolution:**
   - `GET` → `action = "connect"` (SSE stream open, no body)
   - `POST` → `io.ReadAll(r.Body)` → `r.Body` replaced with `io.NopCloser(bytes.NewReader(buf))` → `proxy.Parse(buf)` → `proxy.Action(msg.Method)`; parse failure maps to `action = "unknown"`
4. `enforcer.Enforce(ctx, identity.Roles, serverName, action)` — cache-first, short-circuits on first allow
5. Enforce error → log + fall back to `enforcer.DefaultAllow()`
6. `!allowed` → 403 `{"error":"forbidden"}`

The body buffering pattern (read-replace) is required because `io.ReadAll` consumes the request body; the proxy handler downstream also needs it. `io.NopCloser(bytes.NewReader(buf))` resets the position without allocating a new buffer.

**Why `"connect"` on `GET /sse`:** The SSE stream is a long-lived connection that can carry server-push events from the upstream MCP server. Even before any JSON-RPC method is sent, the upstream may push notifications. A user without a matching policy should not be able to open the channel and receive those events. Enforcing `"connect"` closes the information-leakage and resource-exhaustion vectors. The admin wildcard `p, admin, *, *` covers `"connect"` transparently.

The middleware references `proxy.Parse` and `proxy.Action` — functions in the `internal/proxy` package (not a sub-package). The plan's pseudocode used a `jsonrpc` import path that did not match the actual codebase layout.

### 6.2 `RequireRole`

```go
func RequireRole(role string, logger *slog.Logger) func(http.Handler) http.Handler
```

Applied to the admin API group after `authMiddleware`. Performs a linear scan of `identity.Roles` for an exact match. Logs `rbac: admin access denied` at Info level with `user` and `required_role` fields. Returns 403 `{"error":"forbidden"}` on failure.

Does not use Casbin — a flat "admin role required" check on the admin API group does not benefit from the policy table machinery. Adding Casbin here would require an additional set of policy rows for admin sub-resources with no practical security benefit in Sprint 4.

### 6.3 `writeJSONError` Helper

Defined in `middleware.go` (not in `router.go`) because it is needed at the RBAC layer before the admin API router is reached.

## 7. Admin API Additions

### 7.1 `policies.go`

Three handler methods on `policyHandler` (carries `*rbac.Enforcer` and `*slog.Logger`):

| Method | Route | Notes |
|--------|-------|-------|
| `list` | `GET /api/v1/admin/policies` | Returns `[]PolicyRule`; HTTP 200 |
| `add` | `POST /api/v1/admin/policies` | Body: `{"role","server","action"}`; all three required; HTTP 201 + echo of rule |
| `remove` | `DELETE /api/v1/admin/policies` | Body: same shape; HTTP 204 on success |

Both `add` and `remove` validate that all three fields are non-empty before calling the enforcer. This prevents Casbin from inserting malformed rules that would be impossible to remove or that could act as wildcards unintentionally.

### 7.2 `roles.go`

`roleHandler` with seven handler methods:

| Method | Route | Notes |
|--------|-------|-------|
| `list` | `GET /api/v1/admin/roles` | All roles, ordered by name |
| `create` | `POST /api/v1/admin/roles` | 201; 409 on duplicate name |
| `get` | `GET /api/v1/admin/roles/{id}` | 404 on miss |
| `update` | `PUT /api/v1/admin/roles/{id}` | System roles: `name` field silently ignored (only `description` updated) |
| `delete` | `DELETE /api/v1/admin/roles/{id}` | 409 `"system roles cannot be deleted"` if `is_system = true` |
| `assign` | `POST /api/v1/admin/roles/{id}/users` | Body: `{"user_id":"..."}` → 204; idempotent |
| `revoke` | `DELETE /api/v1/admin/roles/{id}/users/{userID}` | 204; 404 if not assigned |

The system-role guard in `update` reads the role from the store before deciding which fields to pass to `Update`. This keeps the handler in control of which mutations are safe for system roles rather than pushing that logic into the store layer.

### 7.3 `users.go`

`userHandler` with three handler methods:

| Method | Route | Notes |
|--------|-------|-------|
| `list` | `GET /api/v1/admin/users` | All users; page limit 100 (hardcoded for Sprint 4) |
| `get` | `GET /api/v1/admin/users/{id}` | 404 on miss |
| `patch` | `PATCH /api/v1/admin/users/{id}` | Accepts `{"status":"active"|"suspended"}`; all other fields silently ignored; re-fetches and returns the updated user |

`PATCH` only accepts `status`. The re-fetch after `Update` ensures the response reflects the DB state (including `updated_at`) rather than the caller's input.

### 7.4 `router.go` Changes

`Router` struct gains three fields:

```go
roles    store.RoleStore
users    store.UserStore
enforcer *rbac.Enforcer
```

`NewRouter` signature updated from 4 to 7 parameters. All call sites updated (`server.New()` passes the new dependencies).

New route groups wired to `Handler()`:
- `/roles` — full role CRUD + user assignment/revocation
- `/users` — list, get, patch
- `/policies` — Casbin policy CRUD

`/logs` and `/metrics` remain as `notImplemented` stubs — those are Sprint 5/6.

## 10. Pivots and Deviations from Plan

### 10.1 `casbin_rule` Column Nullability

**Plan:** value columns `v0`–`v5` specified as `TEXT NOT NULL DEFAULT ''`.

**Reality:** the `pckhoi/casbin-pgx-adapter/v3` adapter passes `NULL` for unused columns when inserting a 3-field policy rule (e.g. `p, admin, *, *` — only `v0`, `v1`, `v2` are set). Columns `v3`, `v4`, `v5` receive `NULL`, which violated the `NOT NULL` constraint.

**Fix:** all value columns changed to plain `TEXT` (nullable), matching the adapter's own `CREATE TABLE` DDL exactly. This was discovered via an integration test failure:
```
null value in column "v3" of relation "casbin_rule" violates not-null constraint
```

The adapter source was read directly at `$(go env GOPATH)/pkg/mod/github.com/pckhoi/casbin-pgx-adapter/v3@v3.2.0/adapter.go` to confirm the exact DDL.

### 10.2 Admin Wildcard Seeding — SQL vs. Application Code

**Plan (stage-4-plan.md §1):** seed the admin wildcard policy in SQL using a deterministic MD5:
```sql
INSERT INTO casbin_rule (id, p_type, v0, v1, v2)
VALUES (md5('p|admin|*|*'), 'p', 'admin', '*', '*')
ON CONFLICT (id) DO NOTHING;
```

**Reality:** the adapter uses meow hash (not MD5) for the `id` column. The exact hash function is an internal implementation detail not documented in the adapter's README and can change between adapter versions. Predicting it in SQL is fragile.

**Decision:** seeding is done entirely via `SeedDefaultPolicies()` in `server.New()`. The Casbin `AddPolicy` call is idempotent — it returns `false` (not an error) when the rule already exists. The migration creates only the schema and system roles; it contains a comment explaining why the admin policy is omitted.

### 10.3 `GetPolicy()` Return Value

**Plan (pseudocode):** `rules := e.e.GetPolicy()` (one return value).

**Reality:** `casbin.Enforcer.GetPolicy()` returns `([][]string, error)` in Casbin v2. The error is always `nil` for in-memory policy reads but the compiler requires handling both return values.

**Fix:** `rules, _ := e.e.GetPolicy()`.

### 10.4 `proxy.Parse` / `proxy.Action` Import Path

**Plan:** middleware pseudocode imported from `internal/proxy/jsonrpc`.

**Reality:** `Parse` and `Action` are top-level functions in `internal/proxy` (not a sub-package). The import was corrected to `"github.com/K3y5tr0ke/mcpgate/internal/proxy"`.

### 10.5 `NewAdapter` First Argument

**Plan:** `pgxadapter.NewAdapter("", ...)` — empty string connection string.

**Reality:** the adapter's first parameter is `conn *pgx.Conn`, not a string. Passing `nil` is correct when `WithConnectionPool` is provided. Discovered by reading the adapter source; the plan's `""` would not have compiled.

### 10.6 `GET /api/v1/me` — Not in Original Plan

Not in the Sprint 4 plan. Added to resolve the test regressions described in §9.3. The endpoint is a useful addition regardless: it gives any authenticated client a way to inspect their identity and roles without requiring the admin role.

## 13. Key Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| D1 | `pckhoi/casbin-pgx-adapter/v3` with `WithConnectionPool()` + `WithSkipTableCreate()` | Reuses the existing `*pgxpool.Pool`; we own the schema via migrations, not the adapter's auto-create |
| D2 | Migration 003 drops and recreates `casbin_rule` | Schema mismatch (`ptype` vs `p_type`, `BIGSERIAL` vs `text`); table is empty in all environments prior to Sprint 4 so `DROP` is safe |
| D3 | All value columns (`v0`–`v5`) are nullable `TEXT` | Adapter passes NULL for unused columns in short rules; `NOT NULL DEFAULT ''` caused integration test failures |
| D4 | Admin wildcard seeded by `SeedDefaultPolicies()` at startup, not in SQL | Adapter's row ID is a meow hash — not predictable in SQL without coupling to adapter internals that can change |
| D5 | `"connect"` action enforced on `GET /mcp/{serverName}/sse` | SSE channels carry server-push events; unauthorised users must not open the channel even before sending a JSON-RPC request |
| D6 | Body buffered in `Authorize`, not inside proxy handler | Keeps proxy handler transport-agnostic; enforcer sees the method before it is forwarded |
| D7 | `RequireRole("admin")` for admin API, not Casbin | Admin API access is a flat role check; routing through Casbin would require an extra policy table for admin sub-resources with no practical security benefit in Sprint 4 |
| D8 | `PolicyCache.Invalidate()` called synchronously after every policy mutation | Stale allow/deny decisions are a security risk; correctness takes priority over cache efficiency |
| D9 | `RoleStore.Delete` reads before deleting (two queries) | The system-role guard must be a Go-level `store.ErrConflict`; a DB trigger would hide the distinction from the handler |
| D10 | `GET /api/v1/me` endpoint added | Gives non-admin authenticated clients (M2M, SAML JIT) a probing endpoint; resolved test regressions without weakening admin route protection |
| D11 | Casbin `g` (group) rules skipped; roles looped in Go | `UserIdentity.Roles` already carries the user's roles from the session cache; no dual-write to `casbin_rule` is needed; keeps the model simple and the policy table to pure `p` rules |

## 18. Security Properties Delivered

| Threat | Mitigation |
|--------|-----------|
| Authenticated user calls any MCP server | `Authorize` middleware denies without a matching Casbin policy (`DefaultAction: deny`) |
| Unauthorised SSE stream connection receives server-push events | `"connect"` action enforced on `GET /mcp/{serverName}/sse`; no policy → 403 before stream opens |
| Stale cached allow decision after policy revocation | `PolicyCache.Invalidate("rbac:*")` called synchronously on every policy mutation |
| Non-admin user accesses admin API | `RequireRole("admin")` blocks before handler is reached |
| Operator deletes the `admin` system role | `is_system = true` check in delete handler returns 409; `ErrConflict` propagated as HTTP 409 |
| Admin wildcard policy accidentally removed | `SeedDefaultPolicies()` runs on every startup; Casbin is idempotent — the rule is restored |
| Casbin policy injection via JSON body | `AddPolicy` accepts individual string fields only; no raw Casbin rule strings accepted from the API |
| Resource exhaustion via open SSE channels | Unauthorised connect attempts rejected at RBAC middleware before reaching the upstream transport |
