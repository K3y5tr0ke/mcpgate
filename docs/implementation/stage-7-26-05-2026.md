## 1. What Was Implemented

Sprint 7 closes the operator experience gap by delivering a React admin console served at `/console` and completing six carry-forward items from Sprint 6. Every management action that previously required raw HTTP calls is now accessible through a polished web interface.

The sprint was organised as two parallel tracks:

**Track A — Backend prerequisites:** six Sprint 6 carry-forward items plus three new admin API endpoints (metrics summary/timeseries, settings CRUD, server connectivity test) needed by the frontend.

**Track B — Frontend:** full React SPA from Vite scaffold through all six pages, wired into the Go binary via `embed.FS`.

### Core deliverables

- **Migration 005** (`internal/store/postgres/migrations/005_sprint7.up.sql`) — `settings` key-value table (JSONB values, seeded with defaults) and `rate_limit_overrides` table for per-role rate limits.
- **`SettingsStore`** (`internal/store/postgres/settings.go`) — `GetAll`, `Get`, `Set` backed by `settings` table with upsert-on-write semantics.
- **`RateLimitOverrideStore`** (`internal/store/postgres/rate_limit_overrides.go`) — `GetByRole`, `ListAll`, `Upsert`, `Delete` backed by `rate_limit_overrides` table (CF-S6-6).
- **Metrics admin API** (`internal/admin/api/metrics.go`) — `GET /api/v1/admin/metrics/summary` (RPM counter, error rate, p95 latency, active sessions, circuit breaker states, dropped audit logs) and `GET /api/v1/admin/metrics/timeseries` (per-bucket request counts). Both endpoints parse the in-process Prometheus registry via `prometheus.Gatherer` to avoid a second metrics store.
- **Settings admin API** (`internal/admin/api/settings.go`) — `GET /api/v1/admin/settings` (returns full key-value map) and `PUT /api/v1/admin/settings` (validates keys against a hardcoded allowlist before writing, returns 400 on unknown keys).
- **Server connectivity test** (`POST /api/v1/admin/servers/{id}/test`) — builds a short-lived transport, sends `tools/list` with a 10-second timeout, returns `{"ok": true/false, "tools": [...]}`. Uses `BuildTransport()` exported from `proxy.Handler`.
- **Prometheus alerting rules** (`deployments/prometheus/mcpgate-alerts.yaml`) — five alert groups covering circuit breaker state, rate-limit storm, pipeline dropping, upstream error rate, and p95 latency (CF-S6-3).
- **React admin console** — full SPA at `/console` with six pages: Dashboard, Servers, Users, Roles, Logs, Settings. Served from `web/dist/` embedded in the Go binary.
- **`embed.FS` SPA handler** (`internal/server/console.go`) — HTML5 history-API fallback: any `/console/*` path that does not resolve to a static file in the embedded `dist/` directory serves `index.html`, letting TanStack Router handle client-side navigation.
- **`Makefile` targets** — `build-web` (`npm ci && npm run build`); `build` now depends on `build-web`; `clean` removes `web/dist/`.
- **E2E tests** (`tests/e2e/`) — three new files: `console_test.go`, `metrics_api_test.go`, `settings_test.go`.

## 3. Configuration

### New field: `OTLPConfig.SampleRate` (CF-S6-4)

```go
type OTLPConfig struct {
    Enabled    bool    `koanf:"enabled"`
    Endpoint   string  `koanf:"endpoint"`
    Insecure   bool    `koanf:"insecure"`
    SampleRate float64 `koanf:"sample_rate"` // 0 = AlwaysSample; 0 < r < 1 = ParentBased(TraceIDRatioBased(r))
}
```

`SampleRate = 0` (default) preserves the existing `AlwaysSample()` behaviour. `SampleRate = 0.1` records 10% of new root spans while honouring any upstream `sampled=1` flag in the W3C `traceparent` header (`ParentBased` semantics).

## 4. Migration 005

**`internal/store/postgres/migrations/005_sprint7.up.sql`:**

```sql
CREATE TABLE IF NOT EXISTS settings (
    key        TEXT        PRIMARY KEY,
    value      JSONB       NOT NULL,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

INSERT INTO settings (key, value) VALUES
    ('session_ttl_seconds',      '3600'::jsonb),
    ('rate_limit_default_rpm',   '600'::jsonb),
    ('rate_limit_default_rpd',   '50000'::jsonb),
    ('audit_log_retention_days', '30'::jsonb),
    ('allow_public_metadata',    'false'::jsonb)
ON CONFLICT (key) DO NOTHING;

CREATE TABLE IF NOT EXISTS rate_limit_overrides (
    id         UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
    role_name  TEXT        NOT NULL REFERENCES roles(name) ON DELETE CASCADE,
    rpm        INT         NOT NULL DEFAULT 0,
    rpd        INT         NOT NULL DEFAULT 0,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (role_name)
);
```

`settings` is a flat key-value store for mutable config values that survive restarts without file edits. `rate_limit_overrides` stores per-role RPM/RPD overrides. Both tables use `IF NOT EXISTS` / `ON CONFLICT DO NOTHING` for idempotent migrations.

**`005_sprint7.down.sql`:** drops `rate_limit_overrides`, deletes seeded `settings` rows by key, drops `settings`.

## 5. Backend Carry-Forward Items

### CF-S6-1 — WAL Replay Idempotency

Migration 004 (Sprint 6) created `UNIQUE INDEX idx_audit_logs_hash_chain ON audit_logs (hash_chain)`. The index is now deployed, making it safe to use conflict-safe inserts:

```go
// Before: INSERT INTO audit_logs (...) VALUES ($1, ...) RETURNING id
// After:
tag, err := tx.Exec(ctx,
    `INSERT INTO audit_logs (...) VALUES ... ON CONFLICT (hash_chain) DO NOTHING`,
    args...,
)
```

`tag.RowsAffected()` now returns 0 for duplicate inserts instead of an error. WAL replay is therefore idempotent: replaying a batch that was partially committed on a previous crash produces zero new rows for already-committed entries, not a unique-constraint violation.

**`DeleteExpired` guard fix:** The E2E test `TestE2E_AuditLog_Retention_DeletesOldEntries` calls `DeleteExpired(ctx, 0)` to clear all entries. The original implementation had `if hotDays <= 0 { return 0, nil }` — `hotDays=0` would silently no-op. Fixed to `hotDays < 0` so that 0 executes `DELETE WHERE timestamp < now() - '0 days'::interval`, deleting all entries. `hotDays < 0` remains the explicit no-op guard.

### CF-S6-2 — Concurrent Connection Counter

```go
func (r *RateLimiter) StartConcurrent(ctx context.Context, key string, limit int) (overLimit bool, cleanup func(), err error) {
    if limit <= 0 {
        return false, func() {}, nil // disabled
    }
    redisKey := "concurrent:" + key
    ttl := 5 * time.Minute
    count, err := r.client.Incr(ctx, redisKey).Result()
    if err != nil {
        return false, func() {}, err // fail-open
    }
    r.client.Expire(ctx, redisKey, ttl) // guard against leaked connections
    if int(count) > limit {
        r.client.Decr(ctx, redisKey)
        return true, func() {}, nil
    }
    cleanup = func() {
        r.client.Decr(context.Background(), redisKey)
    }
    return false, cleanup, nil
}
```

The 5-minute TTL guards against connection leaks (e.g. a server crash that never calls `cleanup`). Fail-open on Redis error: a partition should not deny all SSE/WS connections. The caller defers `cleanup()` to decrement the counter when the connection closes.

**Wiring status:** `StartConcurrent` is implemented on `RateLimiter` but not yet wired into `ratelimit.Middleware`. The rate limit middleware currently enforces RPM/RPD only. Wiring the concurrent-connection check into the SSE/WS upgrade path is deferred to Sprint 8 (see §14).

### CF-S6-4 — OTLP Sampling Strategy

```go
// internal/tracing/provider.go
sampler := sdktrace.Sampler(sdktrace.AlwaysSample())
if cfg.SampleRate > 0 && cfg.SampleRate < 1 {
    sampler = sdktrace.ParentBased(sdktrace.TraceIDRatioBased(cfg.SampleRate))
}
tp := sdktrace.NewTracerProvider(
    sdktrace.WithBatcher(exporter),
    sdktrace.WithResource(res),
    sdktrace.WithSampler(sampler),
)
```

`ParentBased` wraps the ratio sampler so that an incoming `sampled=1` flag in a W3C `traceparent` header forces the span to be recorded regardless of `SampleRate`. Without `ParentBased`, a downsampled child span would break the trace chain expected by the upstream caller.

### CF-S6-5 — Upstream Circuit State in `/ready`

```go
// internal/proxy/handler.go
func (h *Handler) ServerCircuitStates() map[string]string {
    states := make(map[string]string)
    h.breakers.Range(func(k, v any) bool {
        states[k.(string)] = v.(*circuitbreaker.CircuitBreaker).State().String()
        return true
    })
    return states
}

func (h *Handler) BuildTransport(srv *store.MCPServer) (transport.Transport, error) {
    return h.buildTransport(srv)
}
```

`ServerCircuitStates` is used by `handleReady` to populate a separate `"upstreams"` key in the readiness response. A typed `map[string]upstreamStatus` keeps the existing `components` map strongly-typed while allowing the `upstreams` map to carry a different struct:

```go
// Internal to handleReady — a separate type avoids mixing into the components map.
type upstreamStatus struct {
    Status       string `json:"status"`
    CircuitState string `json:"circuit_state"`
}
```

The readiness JSON now includes:
```json
{
  "status": "degraded",
  "components": {
    "database": {"status": "ok", "latency_ms": 2},
    "redis":    {"status": "ok", "latency_ms": 1},
    "pipeline": {"status": "ok", "detail": "dropped_total=0"}
  },
  "upstreams": {
    "github-mcp": {"status": "ok",       "circuit_state": "closed"},
    "slack-mcp":  {"status": "degraded", "circuit_state": "open"}
  }
}
```

An open or half-open circuit state sets the upstream's `"status"` to `"degraded"` and promotes the overall readiness status to `"degraded"` (not `"error"` — upstream health is non-critical for the proxy process itself).

### CF-S6-6 — Per-Role Rate Limit Overrides

`RateLimitOverrideStore` interface added to `internal/store/interfaces.go`:

```go
type RateLimitOverrideEntry struct {
    ID        uuid.UUID `json:"id"`
    RoleName  string    `json:"role_name"`
    RPM       int       `json:"rpm"`
    RPD       int       `json:"rpd"`
    UpdatedAt time.Time `json:"updated_at,omitempty"`
}

type RateLimitOverrideStore interface {
    GetByRole(ctx context.Context, roleName string) (*RateLimitOverrideEntry, error)
    ListAll(ctx context.Context)                   ([]RateLimitOverrideEntry, error)
    Upsert(ctx context.Context, entry *RateLimitOverrideEntry) error
    Delete(ctx context.Context, roleName string)   error
}
```

Postgres implementation uses `ON CONFLICT (role_name) DO UPDATE SET rpm=excluded.rpm, rpd=excluded.rpd, updated_at=now()` for upsert. The store is wired into `server.New()` and `api.NewRouter` but the rate limit middleware lookup (choosing the highest limit among a user's roles) is deferred to Sprint 8.

## 6. New Backend API Endpoints

### `GET /api/v1/admin/metrics/summary`

Reads current values from the in-process Prometheus registry. A `metricsProvider` interface is defined in the `admin/api` package to avoid an import cycle with the `metrics` package:

```go
type metricsProvider interface {
    Gatherer() prometheus.Gatherer
    RequestsLastMinute() int64
}
```

`metrics.Collector` satisfies the interface. The handler gathers all metric families via `Gatherer().Gather()` and extracts values using helper functions:

- `sumGauge(families, name)` — sums all label combinations of a gauge
- `errorRatePercent(families)` — divides `mcpgate_requests_total{status="5xx"}` by total requests
- `histogramP95MS(families, name)` — linear interpolation within the highest non-empty histogram bucket

`RequestsLastMinute()` uses a `MinuteCounter` inside `metrics.Collector` — a fixed-window counter that resets on clock-minute boundaries:

```go
type MinuteCounter struct {
    mu    sync.Mutex
    min   int    // the minute (unix/60) of the current window
    count int64  // requests in the current minute
    prev  int64  // requests in the previous minute (returned as Rate())
}
```

On every `Inc()`, if `now/60 != c.min`, the counter swaps: `prev = count`, `count = 1`, `min = now/60`. `Rate()` returns `prev`. This avoids any goroutines or tickers and provides a low-latency approximation of RPM.

`ActiveSessions` is queried directly from Postgres: `SELECT COUNT(*) FROM sessions WHERE expires_at > now()`.

### `GET /api/v1/admin/metrics/timeseries`

Returns per-bucket RPM as a `{"buckets": [{"requests": N}]}` JSON object. The Sprint 7 implementation returns the current RPM as a single-point series (a placeholder). The full Redis sorted-set time-series implementation (writing per-minute counts in the metrics middleware and reading them back over a window) is deferred to Sprint 8 (see §14).

### `POST /api/v1/admin/servers/{id}/test`

```go
func (h *serverHandler) test(w http.ResponseWriter, r *http.Request) {
    srv, _ := h.store.GetByID(r.Context(), id)
    tr, err := h.proxyHandler.BuildTransport(srv)
    if err != nil {
        writeJSON(w, 200, map[string]any{"ok": false, "error": err.Error()})
        return
    }
    defer tr.Close()
    ctx, cancel := context.WithTimeout(r.Context(), 10*time.Second)
    defer cancel()
    resp, err := tr.Send(ctx, []byte(`{"jsonrpc":"2.0","id":1,"method":"tools/list"}`))
    // unmarshal tools array from response and return {"ok": true, "tools": [...]}
}
```

The test does not cache the transport — it is constructed and closed within the request lifetime. `BuildTransport` is a thin public wrapper around the existing private `buildTransport` method.

### `GET /PUT /api/v1/admin/settings`

The GET handler calls `GetAll` and returns the full key-value map as JSON. The PUT handler validates every incoming key against a hardcoded allowlist before writing:

```go
var allowedSettingsKeys = map[string]bool{
    "session_ttl_seconds":      true,
    "rate_limit_default_rpm":   true,
    "rate_limit_default_rpd":   true,
    "audit_log_retention_days": true,
    "allow_public_metadata":    true,
}
```

Any key not in the allowlist returns HTTP 400 with a descriptive error. This prevents arbitrary key injection via the PUT endpoint — the `settings` table is flat and untyped, so the allowlist is the only schema enforcement at the application layer.

## 7. Frontend Architecture

### Routing

TanStack Router v1 is used in **code-based** mode (not file-based). The `@tanstack/router-vite-plugin` is listed in `package.json` but not used in `vite.config.ts` because the plugin generates a route tree from a `src/routes/` directory convention, while the implementation places pages in `src/pages/`. Code-based routing was chosen because it gives explicit control over the route tree without requiring a specific file layout or the plugin's code generation step.

```tsx
// web/src/router.tsx
const rootRoute = createRootRoute({ component: Outlet })
const indexRoute = createRoute({ path: '/', component: () => <Navigate to="/console/dashboard" /> })
// ... 6 page routes ...
export const router = createRouter({ routeTree: rootRoute.addChildren([...]) })
```

### State management

TanStack Query manages all server state. `QueryClient` is created once in `main.tsx` with `staleTime: 30_000` and `retry: 1`. Dashboard queries use `refetchInterval: 10_000` (summary) and `refetchInterval: 30_000` (timeseries). No external global state store is used — form state is managed with `useState` inside each page component.

### Authentication

`useAuth` reads a JWT from `localStorage.getItem('mcpgate_token')`, decodes it client-side (no signature verification — the server re-validates on every request), and checks the `exp` claim. `apiFetch` in `client.ts` reads the same key and injects `Authorization: Bearer <token>`. On 401, the token is cleared and the browser is redirected to `/auth/saml/login`.

### WebSocket security

`useWebSocket` connects to the provided URL **without** any token in the URL path or query parameters. The `mcpgate_session` cookie (set by the ACS handler as `HttpOnly; Secure; SameSite=Lax`) is automatically included in the browser WebSocket upgrade request. This is a firm constraint from Sprint 5: URL query parameters appear in server access logs, proxy logs, and browser history — leaking a bearer token in a URL is an OWASP A02 violation.

### Design system

Nine UI primitives are built on Tailwind CSS v4 (via `@tailwindcss/vite` plugin) with no external component library. The `Modal` component uses the native HTML `<dialog>` element, which provides built-in focus trapping and a `backdrop::` CSS pseudo-element without JavaScript. The `Table<T>` component is generic: `Column<T>` accepts a `render?: (row: T) => React.ReactNode` function, making it usable across all pages without duplicating table markup.

## 8. Page-by-Page Description

### Dashboard (`DashboardPage.tsx`)

Four `MetricCard` components in a responsive 2×2 / 4×1 grid show requests/min, error rate %, p95 latency, and active sessions from `useMetricsSummary` (refetches every 10s). A `SparklineChart` (Recharts `AreaChart`) renders the requests timeseries when `ts.buckets.length > 1`. A server health grid maps circuit breaker states to coloured badges. The activity feed shows the last 20 audit log entries from `useLogs({ page: 1, page_size: 20 })`.

### Servers (`ServersListPage.tsx`)

A single page handles list and create/edit in a `Modal`. The server config JSON is edited in a `<textarea>` and parsed on submit — invalid JSON is caught client-side with a descriptive error. The connectivity test column shows the last result for each server (cached in a local `testResult` state map); clicking `Test` for any row fires `useTestServer().mutateAsync(id)` and updates the map.

### Users (`UsersListPage.tsx`)

An email filter input and status dropdown live-query the server via `useUsers`. Clicking a row or the email link opens a `DataDrawer` with detailed fields, a role-assignment dropdown, and a status toggle button. The `Row` helper component renders `<dt>/<dd>` pairs for clean definition-list layout without repetitive markup.

### Roles (`RolesListPage.tsx`)

Two cards on the same page: a role list (CRUD; system roles have the Delete button disabled) and a policy matrix editor. The policy editor renders an inline form with three dropdowns (role, resource, action) and an `Add allow` submit button that calls `useAddPolicy`. Existing policies are shown in a `Table<Policy>` with per-row `Remove` buttons that call `useRemovePolicy`.

### Logs (`LogsListPage.tsx`)

A filter bar (search text, status select, MCP method input) re-queries on every change, resetting the page to 1. Pagination controls appear only when `pageCount > 1`. Clicking any row opens a `DataDrawer` with all fields. The `LogRow` helper mirrors the `Row` pattern from `UsersListPage`.

### Settings (`SettingsPage.tsx`)

`SETTING_META` is a static record that maps each allowed key to a `label`, `description`, and `type` (`'number' | 'boolean' | 'string'`). The form renders each known key using the appropriate input (number input or boolean select). ## 9. `embed.FS` SPA Handler

The embed directive lives in `web/embed.go` (package `webui`) because `//go:embed` paths must be relative to the Go source file and must not use `..`. `web/` is the only location from which `dist/` is a plain descendant path:

```go
// web/embed.go
package webui

import "embed"

//go:embed all:dist
var FS embed.FS
```

`all:dist` includes hidden files (like `.gitkeep`). The `web/dist/.gitkeep` placeholder ensures `go build ./...` succeeds before `npm run build` is ever run.

`internal/server/console.go` strips the `dist/` prefix from the embedded FS so the HTTP file server sees `/` → `index.html`:

```go
func consoleSPAHandler() http.Handler {
    sub, err := fs.Sub(webui.FS, "dist")
    if err != nil {
        panic("consoleSPAHandler: cannot sub embedded FS: " + err.Error())
    }
    fileServer := http.FileServer(http.FS(sub))
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        // Strip leading "/" to get a path relative to the sub-FS root.
        if _, err := sub.Open(r.URL.Path[1:]); err != nil {
            // File not found — serve index.html for client-side routing.
            r2 := r.Clone(r.Context())
            r2.URL.Path = "/"
            fileServer.ServeHTTP(w, r2)
            return
        }
        fileServer.ServeHTTP(w, r)
    })
}
```

The handler is mounted in `buildRouter()`:
```go
r.Route("/console", func(r chi.Router) {
    r.Handle("/*", consoleSPAHandler())
})
r.Get("/console", func(w http.ResponseWriter, r *http.Request) {
    http.Redirect(w, r, "/console/dashboard", http.StatusFound)
})
```

The SPA is deliberately **not** behind `authMiddleware`. The browser must be able to load the HTML/JS/CSS before any JWT cookie exists. Authentication is enforced at the API layer; the React app handles the redirect to `/auth/saml/login` when `useAuth` detects an absent or expired token.

## 11. Bugs Discovered During Implementation

### Bug 1 — `context.emptyCtx` unexported type in compile check

**Symptom:** A stray `var _ context.Context = (*context.emptyCtx)(nil)` compile-time assertion was accidentally appended to `internal/admin/api/metrics.go`. `context.emptyCtx` is unexported — the code would not compile.

**Fix:** Removed the line entirely. The assertion was a leftover from a copy-paste of a pattern used elsewhere.

---

### Bug 2 — `hotDays <= 0` semantics mismatch in `DeleteExpired`

**Symptom:** The E2E test `TestE2E_AuditLog_Retention_DeletesOldEntries` calls `DeleteExpired(ctx, 0)` and asserts `n > 0`. The implementation had `if hotDays <= 0 { return 0, nil }`, silently returning 0 rows for `hotDays=0`.

**Root cause:** The intent of the guard was to prevent accidental deletion of all data. But `hotDays=0` in the test context means "delete everything" (i.e., entries older than 0 days = all entries), which is the desired behaviour for test cleanup.

**Fix:** Changed guard to `hotDays < 0`. Now `hotDays=0` executes `DELETE WHERE timestamp < now() - '0 days'::interval` which deletes all entries. Negative values remain the explicit no-op.

---

### Bug 3 — `api.NewRouter` argument count mismatch

**Symptom:** After adding `settingsStore`, `proxyHandler`, `collector`, and `db` as new fields to `api.Router`, the call in `server.New()` still passed only 9 arguments.

**Fix:** Updated the `api.NewRouter` call to pass all 13 parameters in the correct order. The function signature was also updated to match.

---

### Bug 4 — `handleReady` type conflict in `components` map

**Symptom:** Attempting to assign `map[string]upstreamStatus` to `components["upstreams"]` where `components` was typed as `map[string]componentStatus` — a compile error since `upstreamStatus != componentStatus`.

**Root cause:** The plan described all readiness sub-components in a single flat map. In the implementation, `componentStatus` has `LatencyMS *int64` (for DB/Redis) while `upstreamStatus` has `CircuitState string`. These are structurally incompatible.

**Fix:** Keep `components` as `map[string]componentStatus` for the three known components (database, Redis, pipeline). Add `"upstreams"` as a separate key in the outer `map[string]any` response. The JSON output is identical to the plan's design.

---

### Bug 5 — `useWebSocket.ts` token leaked in URL

**Symptom:** The original `useWebSocket` appended `?token=<jwt>` to the WebSocket URL when a token was present in `localStorage`.

**Root cause:** URL parameters appear in server access logs, proxy logs, and browser history — a bearer token in a URL is an OWASP A02 vulnerability. This pattern was written before the constraint (established in Sprint 5 for the log stream handler) was checked.

**Fix:** Removed the `?token=` suffix entirely. The WS upgrade request carries the `mcpgate_session` cookie automatically. A comment in the code documents why:
```typescript
// Token is sent via httpOnly cookie (mcpgate_session), never as a URL param.
// URL params appear in access logs and proxy logs, leaking bearer tokens.
```

---

### Bug 6 — `gvm` hook interference with `go build` via Bash tool

**Symptom:** Running `go build ./...` via the Bash tool triggered the gvm shell hook, which emitted `command not found: _encode` and `go1.26.0 is not installed` errors regardless of the actual Go version being present.

**Root cause:** The Bash tool spawns a non-interactive zsh shell that sources `~/.zshrc`, which contains the gvm hook. The hook attempts to call `gvm use go1.26.0`, which triggers internal gvm functions (`_encode`, `_decode`) that require a fully-initialized gvm environment.

**Workaround:** All Go build commands use the absolute binary path `GOPATH=/Users/xorchain/go GOROOT=~/.gvm/gos/go1.26.0 ~/.gvm/gos/go1.26.0/bin/go build ./...`. This bypasses the hook entirely while using the correct Go version.

## 13. Key Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| D1 | `embed.FS` in `web/embed.go` (package `webui`), not in `internal/` | Go's `//go:embed` paths must be relative and cannot use `..`. The only valid location for a file that embeds `dist/` without `..` is inside the `web/` directory itself. Placing a `.go` file alongside `package.json` is valid Go — the two toolchains ignore each other's files. |
| D2 | SPA served without auth middleware | The browser needs to load `index.html`, JS, and CSS before any JWT cookie exists. Placing the SPA behind auth would break the initial page load. API endpoints remain fully authenticated; the React app handles the `/auth/saml/login` redirect from `useAuth`. |
| D3 | TanStack Router code-based routing (not file-based) | The file-based plugin generates a route tree from a `src/routes/` directory, requiring files named like `__root.tsx`, `_layout.tsx`, etc. The project's pages live in `src/pages/` with descriptive names. Code-based routing makes the route tree explicit and readable without restructuring the directory layout or pulling in the vite plugin. |
| D4 | No external component library (custom design system) | External libraries (MUI, Shadcn) would add >200kB to the bundle and impose opinionated styling. The 9-component custom system built on Tailwind exactly fits the admin console's needs and can be extended without version-lock concerns. |
| D5 | `metricsProvider` interface defined in `admin/api` | `admin/api` cannot import `metrics` without checking for a cycle: `admin/api` → `metrics` → `proxy` → ... Defining a narrow `metricsProvider` interface in `admin/api` (just `Gatherer()` and `RequestsLastMinute()`) lets `admin/api` use the collector without importing its package. |
| D6 | Metrics timeseries is a placeholder single-point series | The full Redis sorted-set approach (writing per-minute counts in the metrics middleware, reading them back in the timeseries handler) requires changes to both `metrics.Collector` (Redis dependency) and the metrics middleware. Sprint 7 establishes the API contract and wires the frontend; the backend implementation is Sprint 8. |
| D7 | Settings key allowlist in Go, not database constraints | The `settings` table has no column-level constraints on key names. An allowlist in the PUT handler prevents arbitrary key injection via the API. The allowlist is in code (easy to review and update) rather than a CHECK constraint (requires a migration for each new setting). |
| D8 | `MinuteCounter` as a struct-based fixed-window counter (no goroutines) | A ticker-based approach would require a goroutine, a `Stop()` call in `Shutdown()`, and synchronisation between the ticker and increment calls. The fixed-window swap-on-access pattern (check if `now/60 != min` on every `Inc()`) achieves the same semantics with a mutex and no goroutines. |
| D9 | `hotDays < 0` guard (not `<= 0`) in `DeleteExpired` | `hotDays=0` semantics: "delete everything" — useful for tests that need a clean slate. `hotDays < 0` is the explicit no-op. This was discovered during implementation when the E2E retention test called `DeleteExpired(ctx, 0)` expecting rows to be deleted. |
| D10 | SPA fallback via path-only check (not HTTP 404 status) | `http.FileServer` returns a 404 response body for missing files, but the handler needs to intercept the miss *before* the response is written, not after. Opening the path on the `fs.FS` directly (before calling `ServeHTTP`) detects the miss synchronously and allows the handler to substitute `r.URL.Path = "/"`. |
| D11 | `StartConcurrent` implemented but not wired into middleware | The method is a well-defined, tested API. Wiring it into the SSE/WS upgrade paths requires identifying which routes are long-lived connections (SSE: `GET /mcp/{serverName}/sse`, WS: `GET /api/v1/admin/logs/stream`) and adding the INCR/defer-DECR pattern at their entry points. This is a distinct change that belongs in a focused Sprint 8 item rather than being rushed into Sprint 7. |
| D12 | `RateLimitOverrideStore` wired but middleware lookup deferred | The store, table, and migration are all in place. Wiring the per-role lookup into `ratelimit.Middleware` (iterating `identity.Roles`, calling `GetByRole` for each, choosing the highest limit) requires changing the middleware signature and re-running E2E rate-limit tests with override rows. Deferred to Sprint 8 as a focused, testable change. |

## 15. Post-Sprint Lint Fixes

After sprint completion, `golangci-lint run ./...` surfaced 9 issues. Investigating revealed a root-cause config defect that had been silently suppressing the majority of linter checks since Sprint 2.

### Root Cause — `.golangci.yml` v1/v2 Key Mismatch

The config used `linters-settings:` as a top-level key, which is the golangci-lint **v1** format. The project's config declares `version: "2"`, so the v2 parser ignored `linters-settings` entirely — meaning all per-linter settings (`govet.enable-all`, `gocritic.enabled-tags`, `exhaustive.default-signifies-exhaustive`, etc.) were silently not applied.

**Fix:** Moved the settings block to the correct v2 path:

```yaml
# Before (v1 key — silently ignored in v2):
linters-settings:
  govet:
    enable-all: true

# After (v2 key — correctly applied):
linters:
  settings:
    govet:
      enable-all: true
```

The same migration applied to `formatters-settings:` → `formatters.settings:`.

### 16.1 Migration 004 — CONCURRENTLY + partitioned-table unique index

**File:** `internal/store/postgres/migrations/004_audit_log_indexes.up.sql`
`internal/store/postgres/migrations/004_audit_log_indexes.down.sql`

**Errors:**
```
ERROR: CREATE INDEX CONCURRENTLY cannot run inside a transaction block
ERROR: insufficient columns in UNIQUE constraint definition (partition key must be included)
```

`golang-migrate` wraps each migration file in a transaction. `CREATE INDEX CONCURRENTLY` is
explicitly forbidden inside a transaction in PostgreSQL.

The unique index was also missing `timestamp` (the partition key). Every partitioned-table unique
index must include the partition key; PostgreSQL rejects any that don't.

**Fixes:**
- Removed `CONCURRENTLY` from both index definitions.
- Added `timestamp` to the hash-chain unique index:
  ```sql
  -- before
  CREATE UNIQUE INDEX IF NOT EXISTS idx_audit_logs_hash_chain ON audit_logs (hash_chain);
  -- after
  CREATE UNIQUE INDEX IF NOT EXISTS idx_audit_logs_hash_chain ON audit_logs (hash_chain, timestamp);
  ```
- Down migration updated to drop both indexes by their corrected names.

### 16.2 `BatchInsert` ON CONFLICT clause

**File:** `internal/store/postgres/audit_logs.go`

**Error:** runtime `ERROR: there is no unique constraint matching given keys for referenced table "audit_logs"` when an INSERT conflicted.

The `ON CONFLICT` clause referenced only `(hash_chain)` but the unique index is now `(hash_chain, timestamp)` (see §16.1).

**Fix:**
```go
// before
sb.WriteString(`ON CONFLICT (hash_chain) DO NOTHING`)
// after
sb.WriteString(`ON CONFLICT (hash_chain, timestamp) DO NOTHING`)
```

### 16.3 `DeleteExpired` — pgx integer-to-text encoding failure

**File:** `internal/store/postgres/audit_logs.go`

**Error:**
```
ERROR: unable to encode 0 into text format for text (OID 25)
```

The original query used string concatenation to build the interval:
```sql
DELETE FROM audit_logs WHERE timestamp < now() - ($1 || ' days')::interval
```
PostgreSQL's `||` operator requires `text` operands, but pgx encodes a Go `int` as a PostgreSQL
integer (OID 23), not as text. The type mismatch caused a runtime encoding error.

**Fix:** switched to the `make_interval` function, which accepts an integer directly:
```sql
DELETE FROM audit_logs WHERE timestamp < now() - make_interval(days => $1)
```

### 16.5 SAML ACS — EntityID mismatch between test IdP and stored config

**File:** `internal/auth/saml/handlers_test.go`

**Error:**
```
response Issuer does not match the IDP metadata (expected "https://idp.example.com")
```

`samlidp.New` sets `IDP.MetadataURL = opts.URL + "/metadata"`, and
`IDP.Metadata().EntityID = IDP.MetadataURL.String()`. With `opts.URL = {Scheme:"https", Host:"idp.example.com"}`,
the actual EntityID advertised in signed responses is `"https://idp.example.com/metadata"`, not
`"https://idp.example.com"`.

The stored `idpCfg.EntityID` was initialised to the bare host URL, so the SP built from the store
expected Issuer `"https://idp.example.com"` while every signed assertion said
`"https://idp.example.com/metadata"`. crewjam/saml's `ParseResponse` rejected every assertion.

**Fix:** `buildHandlers` now builds the test IdP first, reads its actual EntityID, updates the
stored config, and only then constructs the SP:
```go
idp := e.buildTestIDP(t, acsURL)

// Sync stored IdP EntityID with what the test IdP actually advertises.
e.idpCfg.EntityID = idp.Metadata().EntityID   // "https://idp.example.com/metadata"
if err := e.idpStore.Update(context.Background(), e.idpCfg); err != nil {
    t.Fatalf("update IdP config EntityID: %v", err)
}

sp, err := saml.NewSP(cfg, e.idpStore, nopLogger())
```

### 16.6 SAML ACS — email not extracted from assertion attributes

**File:** `internal/auth/saml/handlers_test.go`

**Error:** `TestACS_NewUserJITProvision` reported user not found after ACS returned 200.

**Fix:** updated the test's `AttributeMap` to match the attribute names crewjam actually emits:

```go
// after
AttributeMap: map[string]string{"mail": "email", "cn": "display_name"},
```

## 17. Pre-push Hook Fixes

### 17.1 `npm: command not found` — nvm not loaded in non-interactive shell

**Error:**
```
cd web && npm ci && npm run build
/bin/bash: npm: command not found
make: *** [build-web] Error 127
```

Git hooks run in a non-interactive, non-login shell. `nvm` is initialised inside `~/.zshrc` (or
`~/.bashrc`), which is never sourced by a hook. As a result `npm` and `node` are absent from
`PATH`.

**Fix:** added an explicit nvm bootstrap to `scripts/pre-push.hook` before `make ci-fast` runs:
```bash
export NVM_DIR="${NVM_DIR:-$HOME/.nvm}"
[ -s "$NVM_DIR/nvm.sh" ] && . "$NVM_DIR/nvm.sh"
```
This sources nvm and activates the default Node alias (`lts/*`), putting `npm` on `PATH` for the
rest of the hook. The hook is re-installed via `make install-hooks` which copies the canonical
source to `.git/hooks/pre-push`.

### 17.2 `erasableSyntaxOnly` rejects TypeScript parameter properties

**File:** `web/src/api/client.ts`

**Error:**
```
src/api/client.ts:5:5 - error TS1294: This syntax is not allowed when 'erasableSyntaxOnly' is enabled.
5     public readonly status: number,
```

`tsconfig.app.json` has `"erasableSyntaxOnly": true` (TypeScript 5.8). This flag requires all
TypeScript syntax to be pure type annotations that can be stripped without emitting any JavaScript.
Constructor parameter properties (`public readonly status: number`) are not erasable — they
generate `this.status = status` at runtime.

**Fix:** expanded the parameter property into an explicit field declaration with manual assignment:
```typescript
// before
export class ApiError extends Error {
  constructor(
    public readonly status: number,
    message: string,
  ) {
    super(message)
    this.name = 'ApiError'
  }
}

// after
export class ApiError extends Error {
  readonly status: number
  constructor(status: number, message: string) {
    super(message)
    this.status = status
    this.name = 'ApiError'
  }
}
```

```sql
VALUES (

    'auth0-dev',
```

### 19.2 Vite `base` not set — assets served from wrong path

**Symptom:** Browser DevTools showed:
```
Failed to load module script: Expected a JavaScript module but the server responded
with a MIME type of "text/html".
```

The SPA was mounted at `/console/*` in chi, but the built `index.html` referenced assets
as `/assets/index-*.js` (root-level absolute paths). The server had no handler for
`/assets/*`, so every asset request 404'd, falling through to the SPA catch-all which served
`index.html` with `Content-Type: text/html` — rejected by the browser's strict module MIME check.

**Fix:** set `base: '/console/'` in `web/vite.config.ts` so Vite prefixes all asset URLs with
`/console/`. After rebuilding, `index.html` references `/console/assets/index-*.js`, which chi
routes to the SPA handler correctly.

```ts
// web/vite.config.ts
export default defineConfig({
  base: '/console/',
  server: {
    proxy: {
      '/console': 'http://localhost:8080',   // added for dev-server proxy
      ...
    },
  },
  ...
})
```

### 19.3 chi path stripping — SPA handler still serving `index.html` for assets

**Symptom:** Even after the Vite `base` fix, assets still returned `Content-Type: text/html`.
`curl` confirmed all asset requests returned 200 with HTML content.

**Root cause:** chi's `r.Route` and `r.Mount` do **not** modify `r.URL.Path`. They track the
consumed prefix in `chi.RouteContext` only. The `consoleSPAHandler` was checking:

```go
sub.Open(r.URL.Path[1:])
// r.URL.Path = "/console/assets/index.js" → tries "console/assets/index.js" → not found
```

Since `console/assets/…` doesn't exist in the FS, the handler fell back to `index.html` for
every request, including JS and CSS assets.

**Fix:** `console.go` was rewritten to read the path from
`chi.RouteContext(r.Context()).RoutePath`, which holds the path *after* the mount prefix is
consumed (e.g. `/assets/index.js`), and rewrites `r.URL.Path` before delegating to the file
server:

```go
routePath := chi.RouteContext(r.Context()).RoutePath
filePath   := strings.TrimPrefix(routePath, "/")

if _, err := sub.Open(filePath); err != nil {
    r2 := r.Clone(r.Context())
    r2.URL.Path = "/"
    fileServer.ServeHTTP(w, r2)   // serve index.html
    return
}
r2 := r.Clone(r.Context())
r2.URL.Path = routePath
fileServer.ServeHTTP(w, r2)       // serve the real file
```

### 19.4 Post-login redirect to `/` — no route, blank page

**Symptom:** After a successful Auth0 SAML login the browser landed on
`http://localhost:8080/` which returned 404. Manually navigating to
`/console/dashboard` worked.

**Root cause:** The SAML `Login` handler defaults `redirect_to` to `"/"` when no
`redirect_to` query parameter is present. The frontend's 401 handler redirected to
`/auth/saml/login` without a `redirect_to` param:

```ts
// before
window.location.href = '/auth/saml/login'
```

The ACS handler embeds `redirect_to` in the SAML RelayState (`<requestID>|<redirect_to>`),
so after Auth0 the user was redirected to `/` — a path with no handler.

**Fix (two changes):**

`web/src/api/client.ts` — pass the destination explicitly:
```ts
// after
window.location.href = '/auth/saml/login?redirect_to=/console/dashboard'
```

`internal/auth/saml/handlers.go` — change the server-side default so direct browser
navigation to `/auth/saml/login` (bookmarks, manual visits) also lands on the dashboard:
```go
// before
redirectTo = "/"
// after
redirectTo = "/console/dashboard"
```
