## 1. What Was Implemented

Sprint 0 delivers a fully scaffolded, runnable skeleton. No proxy logic, no auth, no RBAC — just the foundation every subsequent sprint builds on.

### 1.1 Module and Version Pinning

| File | Purpose |
|------|---------|
| `go.mod` | Module `github.com/K3y5tr0ke/mcpgate`, Go 1.26 |
| `go.sum` | Dependency lockfile (generated by `go mod tidy`) |
| `.go-version` | `go1.26.0` — read by gopls, VS Code Go extension, and CI |
| `.gitignore` | Ignores `bin/`, `certs/`, `configs/mcpgate.local.yaml`, `*.key`, `*.pem`, WAL files |

### 1.2 Configuration System (`internal/config/`)

- **`config.go`** — Full `Config` struct covering all sections from PRD §15: `server`, `database`, `redis`, `auth`, `jwt`, `saml`, `proxy`, `circuit_breaker`, `health_check`, `rbac`, `logging`, `pipeline`, `retention`, `rate_limiting`, `metrics`, `otlp`, `admin`, `servers[]`.
- Loader uses **koanf v2**: YAML file → `MCPGATE_*` env vars → defaults. Merge order: defaults < file < env.
- `validate()` checks port range, required DB fields, and RBAC default action.
- Helper methods: `DatabaseDSN()` (pgx DSN string), `RedisAddr()` (host:port).
- **`config_test.go`** — 4 unit tests: defaults, env override, invalid port validation, invalid RBAC action validation, file loading.

### 1.3 Store Layer (`internal/store/`)

**`interfaces.go`** — All store and cache interfaces defined (no implementations yet):
- `UserStore`, `ServerStore`, `AuditLogStore`, `SessionStore`, `RoleStore` (PostgreSQL)
- `SessionCache`, `PolicyCache`, `RateLimiter` (Redis)
- Domain types: `User`, `Role`, `MCPServer`, `ServerTool`, `AuditLogEntry`, `Session`, `SessionData`
- Filter/pagination types: `UserFilter`, `LogFilter`, `Pagination`, `RateLimit`, `RateLimitResult`

**`store/postgres/db.go`** — `NewPool()`: creates a `pgxpool.Pool` from config, sets `MaxConns`, `MinConns`, `MaxConnLifetime`, validates with `Ping`.

**`store/redis/client.go`** — `NewClient()`: creates a `redis.Client` from config, validates with `Ping`.

### 1.4 Logging (`internal/logging/`)

**`logger.go`**:
- `New(level, format)` — returns a `*slog.Logger` with JSON or text handler at the configured level.
- `WithLogger(ctx, logger)` / `FromContext(ctx)` — stores and retrieves the logger from `context.Context`. Falls back to `slog.Default()` if not set.

### 1.5 HTTP Server (`internal/server/`)

**`server.go`**:
- `New()` builds the chi router and `http.Server` with all timeouts from config.
- Middleware chain: `chimw.RealIP` → `chimw.RequestID` → `chimw.Recoverer` → custom `requestLogger`.
- `requestLogger` — structured logging middleware: logs method, path, status, bytes, latency_ms, request_id.
- `GET /health` — always returns `200 {"status":"ok"}`. No external dependencies checked.
- `GET /ready` — checks DB ping and Redis ping with a 3-second context timeout. Returns `503` with detail message if either is unavailable.
- `Run()` — listens, starts goroutine, waits for `SIGTERM`/`SIGINT`, then calls `http.Server.Shutdown` with a 30-second grace period.
- Placeholder route groups for proxy routes (`/mcp/...`) and admin API (`/api/v1/admin/...`) — both empty, wired in Sprint 1 and Sprints 7–9 respectively.

### 1.7 Database Migrations (`internal/store/postgres/migrations/`)

**`001_initial.up.sql`** — Full schema in a single transaction:

| Table | Notes |
|-------|-------|
| `users` | `status` CHECK constraint: `active \| suspended \| deactivated` |
| `roles` | `is_system` flag prevents accidental deletion of built-in roles |
| `user_roles` | Composite PK `(user_id, role_id)`, `assigned_by` nullable FK |
| `casbin_rule` | Casbin-compatible `ptype / v0–v5` layout; indexed on `ptype` |
| `mcp_servers` | `transport` CHECK: `streamable_http \| sse \| stdio` |
| `server_tools` | Composite PK `(server_id, tool_name)` |
| `audit_logs` | Partitioned `BY RANGE (timestamp)`; PK is `(id, timestamp)` per partition requirement; default partition as catch-all; 6 indexes |
| `saml_idp_configs` | Stores PEM certificate, attribute and group-role maps as JSONB |
| `oauth_clients` | `client_secret` stored as bcrypt hash; `grant_types` and `scopes` as `TEXT[]` |
| `sessions` | Indexed on `user_id` and `expires_at` |
| `set_updated_at()` trigger | Auto-updates `updated_at` on `users`, `mcp_servers`, `saml_idp_configs` |

**`001_initial.down.sql`** — Drops all objects in dependency order (triggers → tables), wrapped in a transaction.

## 2. Decisions Made During Implementation

### D1 — `configs/mcpgate.dev.yaml` is committed, not gitignored

**Original plan:** gitignore `configs/mcpgate.dev.yaml`.  
**Decision:** Commit it; gitignore `configs/mcpgate.local.yaml` instead.  
**Rationale:** The dev config contains only dummy credentials (`devpassword`) that are intentionally public. Gitignoring it would mean every developer needs to create it manually from the example, with no canonical reference for what dev values should be. `mcpgate.local.yaml` is the escape hatch for credentials that should never be committed.

### D2 — Makefile uses direct gvm Go binary path

**Decision:** `GVM_GO := $(HOME)/.gvm/gos/go1.26.0/bin/go`  
**Rationale:** Makefile recipes run in a fresh non-interactive shell per recipe. Shell functions like the `gvm` shell function cannot be sourced reliably across recipe subshells. Referencing the binary path directly is deterministic, requires no shell magic, and works identically for all Makefile targets.

### D3 — CI uses `actions/setup-go`, not gvm

**Rationale:** GitHub Actions runners don't have gvm. Installing and configuring gvm in CI adds ~60 seconds of setup time for no benefit, since the Go version is already pinned via `go-version: '1.26'` in the workflow. gvm is strictly a local developer tool in this project.

### D4 — `audit_logs` DEFAULT partition as catch-all

**Decision:** Created `audit_logs_default PARTITION OF audit_logs DEFAULT` rather than pre-creating monthly partitions.  
**Rationale:** Sprint 0 must not require pg_partman or manual partition pre-creation just to run migrations. The DEFAULT partition is a functional catch-all that works immediately. Monthly partitions should be created (and the DEFAULT partition eventually emptied/dropped) before production launch via pg_partman or a cron job — documented as a TODO below.

### D5 — `cmdMigrate` is a passthrough stub

**Rationale:** Running golang-migrate from inside the binary would require embedding the migration binary or calling `os/exec`, which adds complexity. The Makefile already provides `make migrate-up/down` via the golang-migrate CLI. The `migrate` subcommand simply prints instructions so the binary remains self-documenting.

### D6 — Docker Compose v2 syntax, no `version:` field

**Rationale:** The `version:` key in `docker-compose.yml` was deprecated in Compose v2 and triggers a warning. Using the `name:` top-level field (Compose v2.3+) and omitting `version:` is the current recommended approach.

### D7 — Prometheus/Grafana behind `profiles: [observability]`

**Rationale:** Most development sessions don't need local Prometheus/Grafana. Putting them behind a profile keeps `docker compose up` fast and avoids port conflicts (`9091`, `3000`) for developers who run those services globally. Opt-in: `docker compose --profile observability up`.

### D8 — `go vet` fix in `printUsage()`

**Issue found:** `fmt.Println` with a multi-line string literal ending in `\n` triggered `go vet` warning: "arg list ends with redundant newline".  
**Fix:** Changed to `fmt.Print()` which doesn't append an extra newline.

### 5.2 Infrastructure / Operational TODOs

- [ ] **`audit_logs` partitioning:** The `audit_logs_default` catch-all partition must not be used in production indefinitely. Before go-live: install pg_partman (or add a cron job) to pre-create monthly partitions and detach/archive the DEFAULT partition. Document in `docs/deployment.md`.
- [ ] **`prometheus.dev.yml` on Linux:** `host.docker.internal` resolves correctly on Docker Desktop for Mac/Windows. On Linux (Docker Engine without Desktop), replace with the bridge gateway IP (typically `172.17.0.1`) or use `network_mode: host`. Add a note to `docs/deployment.md`.
- [ ] **`scripts/seed.sh` requires `psql`:** The `setup.sh` prerequisite check does not verify that the `psql` client is installed. Add `check_cmd psql "Install postgresql-client via your package manager"` to `setup.sh`.
- [ ] **`generate-certs.sh` SAN extension:** The `openssl req -addext` flag requires OpenSSL 1.1.1+. Older macOS system OpenSSL (LibreSSL) may not support it. Add a version check or document the minimum OpenSSL version in setup prerequisites.
- [ ] **No `web/` scaffold yet:** The React admin console directory doesn't exist. Vite + React + TypeScript + Tailwind setup is Sprint 7.
- [ ] **No production `Dockerfile` yet:** `deployments/docker/Dockerfile` (multi-stage Go + React build) is Sprint 11. `make build-docker` will fail until then.
- [ ] **No Kubernetes manifests yet:** `deployments/kubernetes/` is Sprint 11.

### 5.3 Code Quality TODOs

- [ ] **`golangci-lint` version compatibility:** `.golangci.yml` uses `version: "2"` format. Verify the installed `golangci-lint` version supports it (`golangci-lint --version` should be ≥ v1.64). If older, downgrade config to `version: "1"` format.
- [ ] **`requestLogger` in `server.go` uses `chimw.NewWrapResponseWriter`:** This captures status and bytes but doesn't add trace/session context to log lines yet. In Sprint 6 (OpenTelemetry), replace with an OTel-aware middleware that injects `trace_id` into every log line.
- [ ] **`server.go` health handler silences `json.Encode` errors:** `_ = json.NewEncoder(w).Encode(v)` discards the error. This is acceptable for the skeleton; add proper error handling once the observability layer is in place (Sprint 6).
- [ ] **Integration tests not yet written for `store/postgres` and `store/redis`:** These packages have no `_test.go` files. Integration tests using `testcontainers-go` will be added alongside each store implementation in Sprints 1–4.
- [ ] **No `internal/proxy/` package yet:** The proxy handler, JSON-RPC parser, transport adapters, and connection pool are all Sprint 1 work. The `internal/server/server.go` placeholder route groups (`// Proxy routes`) are the integration points.

### 5.4 Security TODOs (pre-launch checklist)

- [ ] Replace `devpassword` in `configs/mcpgate.dev.yaml` with a secrets-management approach before any staging or production deployment.
- [ ] Verify `certs/` is always gitignored — the `.gitignore` rule covers it but double-check with `git status` before any commit touching `certs/`.
- [ ] `seed.sh` creates `admin@mcpgate.local` with no password — this user can only authenticate via SAML. Ensure the SAML flow is set up before exposing the admin console externally.
- [ ] Review `gosec` exclusion `G115` (integer overflow) after Sprint 5 (logging pipeline) where integer arithmetic is used in batch sizing.
